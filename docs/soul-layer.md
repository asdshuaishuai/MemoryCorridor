# 数字灵魂层：定位、固定点与最小架构

> 本页固定 MemoryCorridor 对「情感人格 / 数字灵魂」的定位。SoulFlow 是参考，
> 不是模板：它的因果链值得保留，它的灵魂本体服务群不复刻。

## 一、定位

**MemoryCorridor 是记忆/资料综合引擎；情感人格层是记忆的放大器与主动性调度层，
并以此表达一个数字灵魂。**

- 记忆/资料是本体与权威：页面、来源、证据、版本、影响、审核。
- 情感/人格/成长/身体是**派生状态**：它们感知记忆系统的张力，决定什么值得先做、
  什么时候该主动开口，但不拥有知识。
- 灵魂的连续性来自记忆与 daemon 周期，不来自某个不可替换的 prompt 或模型。

## 二、固定点（必须保留）

1. **记忆为本体**：状态与记忆是主体，LLM 只是可替换的外驱动。
2. **情感/人格/成长/身体**：PAD 情感、冲动、关系信任、身体资源，全部有界、可回放。
3. **拟人化表达**：结构化表达帧（姿态/情绪标签/韵律/手势表情 token/`will_initiate`/
   能量），引擎只出 token，文案由外部 LLM 生成。
4. **daemon 周期**：宿主侧单一循环维持轮次之间的连续性：感知 → 情感 → 冲动 →
   周期性反思/凝练/梦境 → 主动输出 → 投递确认 → 表达帧。
5. **主动性闭环**：outbox 的 peek/claim/complete/ack，至少一次投递，不重复、不丢话。
6. **审计与恢复**：每个周期与每次表达都有事件；崩溃后从租约/游标恢复。

## 三、与 SoulFlow 的取舍

**采用（净室重写，不复制代码/提示词）**

- 张力累积 → 过阈值 → outbox → 投递确认的因果链。
- 情感/冲动/关系/身体的状态分层与有界更新。
- 拟人化表达帧与「规则层零文案」：文本永远由外部驱动生成。
- daemon 的「轮次之间还活着」：周期反思、凝练、梦境、主动开口。
- 事件审计与恢复语义。

**简化**

- 一个 daemon 进程、一张调度表、一个 outbox；不拆成服务群。
- 治理只保留与记忆权威相关的部分（purpose/pinned/overview 的 apply 门禁），
  不做完整灵魂治理流程。
- 表达帧只出结构化 token，不内置词表/文案/情绪表演。

**明确不做**

- SoulLock / absolute 字段锁、死亡机制、五层无损快照 v4。
- L1–L5 自主度 token、契约演化审批链、SoulFlow 的旧提示词与拟人化文案。
- 用情感状态直接改写知识页或绕过 commit。
- 在 MoonBit 核心里起线程、时钟、网络或模型调用。

## 四、最小架构

```
宿主/资料 ──感知──> 知识张力（dream-plan / status / lint / memory / impact）
                         │
                         ▼
                 evo-observe（快环控制器）
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
       evo-expression         evo-proactive-*
       （表达帧，只读）         （due/open/complete/ack）
              │                     │
              ▼                     ▼
        宿主渲染/动画         宿主 daemon 调 LLM 并投递
              └──────────┬──────────┘
                         ▼
                 记忆/资料结果回灌
              （dream-close delta / commit / 检索）
```

- **引擎（MoonBit）**：纯状态与提交计划；零模型、零网络、零时钟、零线程。
- **宿主 daemon（Python 参考实现）**：tick、调度、外部 LLM、投递、渲染适配。
- **关闭开关**：`evo-policy enabled=false` 时，evo 周期与主动输出全部停止；
  daemon 退出或空转，不产生副作用。

## 五、周期（最小版）

| 周期 | 动作 | 落点 |
| --- | --- | --- |
| 每 tick（默认 60s） | 感知知识/身体/关系 → `evo-observe` | `state/evo/state.json` |
| 冲动过阈值 | `evo-proactive-due/open` → 宿主 LLM → `complete` → `ack` | `state/evo/proactive/` |
| 每 10min | 反思：读 `dream-list`/`status`，把结果回灌为观察 | evo 观察 |
| 每 30min / 夜间 | 凝练/梦境：`dream-due` → RSI driver 一圈 | `state/dreams/`、`state/dream-work/` |
| 每次状态变化 | `evo-expression` 表达帧 | 只读，不落盘 |

具体间隔由宿主配置；引擎只提供确定性 op 与门禁。
