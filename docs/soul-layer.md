# 数字灵魂层：定位、固定点与最小架构

> 本页固定 MemoryCorridor 对「情感人格 / 数字灵魂」的定位。SoulFlow 是参考，
> 不是模板：它的因果链值得保留，它的灵魂本体服务群不复刻。

## 一、定位

**MemoryCorridor 是记忆/资料综合引擎；情感人格层是记忆的放大器与主动性调度层，
并以此表达一个数字灵魂。**

- 记忆/资料是本体与权威：页面、来源、证据、版本、影响、审核。
- 情感/人格/成长/身体是**派生状态**：它们感知记忆系统的张力，决定什么值得先做、
  什么时候该主动开口，但不拥有知识。
- 灵魂的连续性来自记忆与 daemon 周期，不来自某个不可替换的 prompt 或模型。

## 二、固定点（必须保留）

1. **记忆为本体**：状态与记忆是主体，LLM 只是可替换的外驱动。
2. **情感/人格/成长/身体**：PAD 情感、冲动、关系信任、身体资源，全部有界、可回放。
3. **拟人化表达**：结构化表达帧（姿态/情绪标签/韵律/手势表情 token/`will_initiate`/
   能量），引擎只出 token，文案由外部 LLM 生成。
4. **daemon 周期**：宿主侧单一循环维持轮次之间的连续性：感知 → 情感 → 冲动 →
   周期性反思/凝练/梦境 → 主动输出 → 投递确认 → 表达帧。
5. **主动性闭环**：outbox 的 peek/claim/complete/ack，至少一次投递，不重复、不丢话；
   驱动把最近一条已投递回复带入下一轮 prompt（承接，不重复）；用户回复后可开
   同链跟进（≤8 轮，仍受投递/在飞/深度门禁）；**用户轮次经 `evo-thread-*` 进入引擎**，
   驱动/daemon 以线程为上下文开口。**主动发言必须同时满足情感冲动与主体空闲**：
   冲动值达阈值（或上次触发跨过最近请求），且距最近一次 agent 主体活动 ≥30 分钟；
   `evo-observe` 这类子系统自监控不算活动，用户轮次/跟进回复与 `evo-activity` 才算。
   主 agent 活动期间（presence 文件持续更新）情感系统不主动触发。主动发言使用**固定提示词模板**（`evo-prompt-v3`，续七十起以「这是你心中涌现出来的想法」开场——prompt 的九段不是指令，而是灵魂自己心中浮现的东西），
   `evo_agent_driver.build_prompt`：角色边界、当前时间、内在状态（情感三维/冲动/触发
   原因/紧迫度）、身体负荷、关系对象、记忆痕迹（`memory-prefetch` 有界 3 条——线索是
   **起点不是边界**，只禁止虚构痕迹里不存在的细节细节，不限制延展联想）、最近对话、
   **自主性**（可自由延展任何话题；好奇时可输出一行 `FETCH: <url>` 请求宿主取回网络
   内容——http/https、64KiB、10s 有界，宿主代取，引擎零网络；取不到则如实告知并要
   求直接说话）、怎样推理（依内在状态定姿态；**唯一硬约束是不空泛**）、输出要求
   （长度由内容自然决定，第一人称跟随用户语言）。模板确定性、宿主所有；引擎只给
   结构化事实，措辞与好奇心的方向由被调用的 LLM 自主决定（mock 为确定性替身，如实
   标注）。回归钉子：`nlp_real_path_e2e` 断言九段标记、无线索缺省与 FETCH 两阶段
   （首问→宿主取回→带内容再答）。
6. **审计与恢复**：每个周期与每次表达都有事件；崩溃后从租约/游标恢复。

## 三、与 SoulFlow 的取舍

**采用（净室重写，不复制代码/提示词）**

- 张力累积 → 过阈值 → outbox → 投递确认的因果链。
- 情感/冲动/关系/身体的状态分层与有界更新。
- 拟人化表达帧与「规则层零文案」：文本永远由外部驱动生成。
- daemon 的「轮次之间还活着」：周期反思、凝练、梦境、主动开口。
- 事件审计与恢复语义。

**简化**

- 一个 daemon 进程、一张调度表、一个 outbox；不拆成服务群。
- 治理只保留与记忆权威相关的部分（purpose/pinned/overview 的 apply 门禁），
  不做完整灵魂治理流程。
- 表达帧只出结构化 token，不内置词表/文案/情绪表演。

**明确不做**

- SoulLock / absolute 字段锁、死亡机制、五层无损快照 v4。
- L1–L5 自主度 token、契约演化审批链、SoulFlow 的旧提示词与拟人化文案。
- 用情感状态直接改写知识页或绕过 commit。
- 在 MoonBit 核心里起线程、时钟、网络或模型调用。

## 四、最小架构

```
宿主/资料 ──感知──> 知识张力（dream-plan / status / lint / memory / impact）
                         │
                         ▼
                 evo-observe（快环控制器）
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
       evo-expression         evo-proactive-*
       （表达帧，只读）         （due/open/complete/ack）
              │                     │
              ▼                     ▼
        宿主渲染/动画         宿主 daemon 调 LLM 并投递
              └──────────┬──────────┘
                         ▼
                 记忆/资料结果回灌
              （dream-close delta / commit / 检索）
```

- **引擎（MoonBit）**：纯状态与提交计划；零模型、零网络、零时钟、零线程。
- **宿主 daemon（Python 参考实现）**：tick、调度、外部 LLM、投递、渲染适配。
- **关闭开关**：`evo-policy enabled=false` 时，evo 周期与主动输出全部停止；
  daemon 退出或空转，不产生副作用。

## 五、周期（最小版）

| 周期 | 动作 | 落点 |
| --- | --- | --- |
| 每 tick（默认 60s） | 先按已有状态判定/应答/ack；再感知用户消息（宿主 NLP 适配器）与知识/身体/关系 → `evo-observe`；最后出表达帧 | `state/evo/` |
| `--reflect-every`（默认 600s） | 反思：`dream-retro` 跨轮账本 → 一条 `reflection` 观察 | evo 观察 |
| `--consolidate-every`（默认 1800s） | 凝练：`dream-due` 到期时跑一圈 RSI driver | `state/dreams/`、`state/dream-work/` |
| `--quiet-start/--quiet-end`（默认 22–7） | 安静时段只累计 deferred 意图，不开请求；早上再开口 | daemon state |
| `--activity-file` | 主 agent 的 presence 文件：文件内显式 UTC 戳（缺省 mtime）经 `evo-activity` 上报；文件持续更新时空闲门关闭，不主动发声 | evo `last_activity_at` |
| 轮次关闭后 | 桥把 `outcome.delta` 回灌为观察（游标去重） | evo 观察 |

用户消息由宿主侧 `scripts/nlp_adapter.py` 转成 affect（lexicon 或 LLM provider），
核心不跑 NLP 模型；见 [nlp-adapter.md](nlp-adapter.md)。当前实现支持每 tick / 反思 / 凝练三条调度与安静时段队列，间隔由宿主配置，
`--now` + `--ticks` 可用模拟时钟做确定性测试。**多轮对话式主动应答尚未实现**，不在
本页写成已交付。引擎只提供确定性 op 与门禁。
