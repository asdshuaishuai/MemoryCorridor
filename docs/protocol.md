# CLI、MCP 与工单

开发工具链：MoonBit `moon 0.1.20260920` / `moonc v0.10.14+7d59c7ec9`。目前验证 macOS/POSIX native。引擎不内嵌工具链；初始化、状态变更、页面渲染以及目录文本变化后的首次读取会调用本机 `moon check --deny-warn`。成功结果写入可重建的 `.corridor/catalog-compile.json`，绑定完整 `index.mbt.md` 字节哈希和目录 IR 指纹，后续读取复用收据，收据缺失/损坏/不匹配会重新编译。编译失败不会让运行期解析首个目录块绕过后续 `mbt` 代码块。

## CLI

运行 `_build/native/debug/build/cli/cli.exe`；stdin 每行一个 JSON 请求，stdout 恰好一个终态 JSON。编译器日志走 stderr；EOF 或 `:exit` 退出。首选会话模式是一个进程绑定一个 vault：先发送 `session-open`，随后请求可省略 `vault`，`session-close` 释放会话锁，跨 vault 请求会被拒绝。为兼容旧宿主，未显式打开时首个带 `vault` 的请求会绑定该根目录；后续 legacy 请求仍须携带同一 `vault`，每次操作单独持有 OS 写锁，不能切换到其他 vault。请求上限 2 MiB，单文件上限 16 MiB。wasm 服务面（见 docs/wasm.md）的请求经宿主分段装载达同一 16 MiB 上限，超限回复 `input_overflow` 且不回显 request_id（与 native 对超长请求的行为一致）。

```json
{"op":"session-open","vault":"/absolute/my-vault"}
{"op":"init","purpose":"研究目标"}
{"op":"scan","vault":"/absolute/my-vault"}
{"op":"plan","vault":"/absolute/my-vault"}
{"op":"context","vault":"/absolute/my-vault","order":"64位工单哈希"}
{"op":"analysis-submit","vault":"/absolute/my-vault","order":"64位工单哈希","analysis":{"entities":[],"concepts":[],"conflicts":[],"summary":"分析"}}
{"op":"commit","vault":"/absolute/my-vault","order":"64位工单哈希","pages":[],"at":"2026-10-16"}
{"op":"search","query":"知识","budget":4096}
{"op":"session-close"}
```

成功响应为 `{ok:true,op,result,request_id}`，失败为 `{ok:false,error,error_code,hint,request_id}`；`error` 保留详细可读文本，`error_code` 是稳定分类，`hint` 给出下一步修复动作。结构性拒绝还会附带 `violations:[{predicate,detail,fix,page?}]`，便于 Agent 逐项修复；CLI 与 MCP 使用同一 MoonBit 生成逻辑。`request_id` 可选并原样返回。`list-tools` 无需 vault，返回允许字段和 JSON Schema。未知操作、未知字段及类型错误均拒绝。

进度是显式结构化事件，不写入终态结果也不混入普通日志。CLI 请求增加 `progress:true` 后，会在唯一终态响应前输出 `{"event":"progress","op":...,"phase":"started|completed|failed","request_id":...}`；省略该字段保持每请求一行的兼容行为。MCP `tools/call` 在 `_meta.progressToken` 存在时发送标准 `notifications/progress`，`progress` 为 `0` 或 `1`，终态响应仍只有一个。

`evo/` sidecar（续六十二）：情感/人格子系统的全部记录（policy/state/population/genomes/fossils/proactive/threads/events）自续六十二切片二起位于金库根的 `evo/` 目录，**不在目录清单内**：不参与 `index.mbt.md`、目录指纹、`verify`、`read-log` 与 `pack`。完整性由 sidecar 自有机制保证——`evo/index.json`（路径→SHA-256 mini-catalog，canonical 确定性）+ `evo/transactions/pending.json` 两阶段 journal（先 journal 后文件后换 index 后清 journal；中断后下一个 evo op 前滚恢复到唯一一致态），每条写入过 `@core.validate_record` 封闭 schema；外部字节改动 `evo_sidecar_corrupt` 失败关闭，冲突写 `evo_sidecar_write_conflict` 零副作用。pre-sidecar 金库（`state/evo/…`、`state/events/evo-…`）在第一个启用态 evo op 自动迁移：记录进 sidecar、金库副本与目录行删除；disabled 金库零写入、不迁移，仅经只读 legacy policy 回退保证门判定正确。**代价（e2e 固定）**：pack/unpack 不携带 evo 状态——解包金库无情感态，需重新 enable+init；纯 evo 序列（observe/evaluate）不改金库指纹与目录字节。错误码另含 `evo_sidecar_path_invalid`/`evo_sidecar_path_reserved`/`evo_sidecar_duplicate_change`/`evo_sidecar_recovery_required`。

字典 schema 会准确区分数组元素：`queries`、`sources`、`capabilities` 是字符串数组，`pages`、`items`、`evo-observe-batch.rows` 是对象数组；`space`、`query_vector`、`vector_candidates`、provider job 的 `request/result` 是对象。整数参数还携带与引擎一致的 `minimum/maximum`：`read-log.limit` 为 `0..1000`，搜索 `limit` 为 `1..100`、`budget` 为 `1..65536`、`hops` 为 `0..2`，图 `hops` 为 `0..8`，`embedding-plan.limit` 为 `1..128`，`dream-plan.limit` 为 `1..500`，`workspace-wiki-plan.limit` 为 `1..500`，`memory-prefetch.limit` 为 `1..50`，`read-source` 的 `start`/`end` 为 `0..16777216`，`evo-observe.step` 为 `1..2147483647`，`evo-init.seed` 为 `0..4294967295`。number 字段包括 `page-redundancy.cosine_floor`（`0.0..1.0`）、`evo-observe.salience`（`0.0..1.0`）与 `evo-observe.valence`（`-1.0..1.0`）；引擎端同时拒绝 NaN/无穷（见下）。CLI 与 MCP 从同一 MoonBit 字典生成并在门禁中逐项对账。

## 页面生成与来源

`raw/` 原件可以是任意格式，以原始字节 SHA-256 登记。目录行的 `format` 是已验证的内容契约：Markdown/HTML、图片和代码语言分别记录为 `markdown`、`html`、`image` 或语言名，未知后缀为 `binary`；视觉服务和工单上下文都使用该登记值，不在运行时重新猜测。已知文本格式的 `context` 返回 `source_text`。OOXML 原件（`office-word`/`office-spreadsheet`/`office-slides`，即 `.docx`/`.xlsx`/`.pptx`）由引擎自身做确定性正文抽取：`context` 返回正文文本（Word 段落/制表符语义、Excel 按工作簿顺序的 `# sheet <名>` 表格行、PowerPoint 按编号顺序的 `# slide <n>` 段落），并附 `extraction:{kind,extractor:"corridor-office-v1"}`；损坏、加密、不支持的压缩方法或超出展开上限（32 MiB）的包以稳定错误族拒绝，绝不返回部分文本。HTML 原件（`html`，即 `.html`/`.htm`）同样走引擎自抽通道（续十七）：`context` 返回可见正文（`<script>`/`<style>`/`<template>` 内部剔除、`title` 首行、块级边界成行、`pre` 保留缩进、实体数值形态非法码位拒绝、非 UTF-8 字节拒绝并说明宿主应先转码），并附 `extraction:{kind:"html",extractor:"corridor-html-v1"}`；未闭合的 script 类区域以 `html_unterminated_*` 拒绝而非发布截断正文。图片与其他 `binary` 在 native 宿主配置 OCR 适配器时，`scan`/`refresh` 会按导入的 PDF/图片工单调用本地适配器、按登记字节哈希入账 sidecar，随后 `context` 直接返回 `source_text`（未成功时 context 兜底重试；OCR 是唯一模型例外，执行在 nativehost/platform，WASM 与 `agent` 不提供）；未配置适配器、WASM 面或抽取失败时仍返回 null 和 `extraction_required:true`，由宿主负责提取，不能假称可直接全文搜索。`read-source` 始终把 OOXML 当作字节容器报告（`textual:false` + 体积），抽取文本以 `context` 为准——登记字节完整性与正文投影是两个通道。旧版六字段目录缺少 `format` 时按 `kind/path` 推导并可读取，重新生成目录会写入七字段行。

raw 条目的 `id` 必须与 `path` 完全相同。页面 `sources[]`、事实证据和来源失效传播都以这个相对路径作为稳定引用；目录如果把同一原件登记成不同 id/path，校验会拒绝，`lint` 会返回 `raw_identity_mismatch`。

### Extraction sidecar（宿主抽取结果入账）

模型推理（OCR、PDF 正文抽取、网页解析）始终在宿主侧：核心引擎（`base → agent`）不调用模型或网络；唯一例外是 nativehost 在 `context` 抽取阶段执行本地 OCR 适配器（见 `docs/ocr.md`，WASM 不提供）。`extraction-submit`（字段 `source/kind/extractor/version/text/at`，全部必填字符串）把宿主抽取结果入账为一等公民数据，存成 `state/extractions/<source sha256>.json` 的 sidecar 记录，内容与文件名都绑定登记字节的 SHA-256（`{source, source_sha256, kind, extractor, version, text, submitted_at}`，canonical JSON；文件名哈希必须是 64 位小写十六进制且等于内容 `source_sha256`，否则 `extraction_record_identity_invalid`）。约束与生命周期语义：

- `source` 必须是当前**有效**（active）的 raw 条目且 `textual=false`（`binary`/`image`）。文本类来源已有 `context`/`read-source` 直接通道，外部入账被 `extraction_source_textual` 拒绝；OOXML/HTML 原件走引擎自身的确定性抽取（续十一/续十七），外部结果**不能覆盖**该通道——`extraction_override` 拒绝。已撤销或缺失的条目报 `extraction_source_stale`。submit 另有一道 `source_changed` 字节比对（`agent/extraction.mbt:53`）：它被更早的 `verify`（对 active raw 先报 `source_missing_or_changed`，见下）遮蔽，属纵深防御，登记在[未触达分支](unreachable-branches.md)。`text` 上限 1 MiB **UTF-8 字节**（`extraction_text_invalid`；与 native/MCP 面 2 MiB 请求行上限同口径——宿主按原始 UTF-8 发送正文即可容纳，`\uXXXX` 转义形态行宽约 2–3 倍、超限由传输层先拒）；`submitted_at` 为 ISO 时间串。
- 重放与冲突按 `(source_sha256, extractor, version)` 判定：逐字相同的 `text` 返回 `replayed:true` 且不写第二条记录；同通道不同文本拒绝 `extraction_conflict`，绝不静默覆盖；同一字节哈希上换 extractor/version 拒绝 `extraction_exists:<current>`（详情段是当前持有者 `extractor:version`）。**sidecar 对给定字节哈希是一次性登记**：`forget` 撤销来源后同字节重扫不会复活（`scan` 的墓碑规则），换 version 再提交仍撞 `extraction_exists`；唯一的恢复路径是替换来源字节、`scan` 出新哈希、按新哈希重新入账，旧 sidecar 由 `lint` 报 `extraction_source_stale`/`extraction_source_drift`。不存在"撤销后原字节重新入账"或"同哈希换通道"的通道——hint 表与 `tools.mbt` 描述按此口径写。
- 每次真实提交在 `state/events/extraction-submit-<source sha256>.json` 登记事件（事件文件名绑定来源哈希，改写照不到别处）。盘上残留同哈希事件而目录没有 sidecar 记录时拒绝入账（`extraction_event_conflict`）：审计痕迹与目录必须同时存在或同时不存在，孤儿事件不得被新提交悄悄接管。
- `page-redundancy`（只读语义冗余检测，续二十三）：入参 `space`（必填，对象）、可选 `limit`（1..1000，默认 200）与可选 `cosine_floor`（0.0..1.0 有限小数，默认 0.92，续二十七）。对**活跃非 stale 页面**成对提名近冗余，信号优先级：词元序列恒等（`similar_text`，格式化级差异，两侧都过 64 字节闸）> 同 `space` 向量余弦 ≥ `cosine_floor`（`vector_cosine`，抓改写/同义——唯一能识别"同义改写"的信号）> 共享来源 + 高词元重叠（`shared_source`，弱提名，仅当无更强信号时）。向量只读该 space 且页向量 `sha256` 等于当前页哈希的记录（改写页的旧向量因内容版本闸不再提名）。`cosine_floor` 是**调档声明而非真值常量**：0.92 是文本空间的保守默认，不同宿主向量空间（如视觉空间）应显式声明合适的档位（例如 0.995）；引擎保持模型无关，不按 space 名特判，响应回显 `cosine_floor` 实际生效值使每批提议可审计，越界/非数/NaN/无穷按 `invalid_number` 拒绝，调档只影响 `vector_cosine` 信号、`similar_text` 与 `shared_source` 与其正交。按页 id 稳定选 keeper、首个 keeper 吸收传递组，输出 `{keeper, duplicate, reason, score, signals[]}` 提议组 + `counts`/`fingerprint`。**全程只读、绝不写库、绝不自动合并**——与 `memory-candidates` 同哲学，宿主经现有 commit/编辑流程去合并。`redundant_page` 是配套的确定性 lint 谓词（warning，仅词元近似，不依赖向量、不进 quality-audit 债务面）。

- `dream-plan`（只读梦境，续二十八）：入参可选 `space`（对象）与 `limit`（1..500，默认 50）。在**当前已实现的知识状态**上汇总确定性改进机会：lint 错误/警告、`redundant_page` 冗余页、未被任何页面引用的 raw（`uncovered_source`）、漂移待重析页（`stale_page`）、链接少于两条的综述页（`sparse_topic`），以及给出 `space` 时 `embedding-plan` 口径的缺失向量（`missing_vector`）。返回 `metrics`（pages/stale_pages/lint_errors/lint_warnings/redundant_pages/uncovered_sources/sparse_topics/missing_vectors 八项确定性计数）、按（类别优先级, id）稳定排序的 `opportunities`、`remaining`、`report_hash`（全量机会集的规范哈希，跨 limit 稳定）与 `fingerprint`。可选 `workspace` 时必须显式 `at`：额外返回 `memory`（该工作区 `active/session/conflicted/invalid/drifted/episodes/profiles/prune` metrics 与 `memory_merge/memory_prune/memory_conflict/memory_source_stale/memory_promote` 机会），仍然只读、不调模型、不写库。**只读、不调模型、不写库**——对应 Dream-RSI 的 replay-simulator 梦面，宿主据此决定改哪些页。
- `dream-open`（写，续二十八）：入参 `baseline`（必须等于当前目录指纹，否则 `dream_stale_baseline`）、可选 `policy`（≤8 个标量键值，数字/布尔/≤64 字节字符串）、可选 `space`、`at`。创建 `state/dreams/<id>.json` 轮次记录（id = hash(dream-v2, baseline, policy, space, workspace, at)）与 `state/events/dream-open-<id>-<hash(at)>.json` 事件：记录冻结当时的 metrics、记忆 metrics（`workspace` 非空时）与 `opportunities_hash`，状态机 `open → retained|rejected`。同参重放返回 `replayed:true`（**重放判定先于基线校验**：开一轮本身会移动指纹）；不同身份同 id 不可能发生（id 由身份派生）。
- `dream-close`（写，续二十八）：入参 `id`、`decision`（`retained`/`rejected`）、`at`、可选 `note`（≤1024 字节）。关闭轮次并重算当前 metrics，把前后差值写入 `outcome.delta`（可为负）与 `outcome.metrics`，同时写 `state/events/dream-close-<id>-<hash(decision+at)>.json`。**兼容性门禁（RSI-Anything）**：`retained` 要求当前 `lint_errors` 与 `uncovered_sources` 相对轮次基线不得增加（分别 `dream_compat_lint_regression` / `dream_compat_evidence_loss`）；工作区轮次还要求 `conflicted/invalid/drifted/prune` 不得增加（`dream_compat_memory_regression:<field>`），并在 `outcome.memory`/`outcome.memory_delta` 记录前后值；`rejected` 无门禁但同样记录 outcome 供经验抽取。同决定+同时刻+同 note 的重放返回 `replayed:true`，任何与已决轮次不同的关闭请求按 `dream_terminal` 拒绝。
- `dream-list`（只读，续二十八）：列出所有轮次 `{id,at,status,baseline,metrics,decision,closed_at,outcome}` 与 `counts`；`state/dreams/policy.json` 是节奏记录而非轮次，列举时跳过（续三十四修复）。`lint` 附加跨记录谓词 `dream_round_stale`（warning）：open 轮次的 baseline 已不等于当前指纹时提示关闭或重开——对应 Harness² 的「轮次经验必须收口」而不是悬空。

- `dream-note-submit`（写，续八十二）：记录一条梦境 RSI 笔记提案到 `state/dream-notes/<id>.json`。`kind` 取 `insight`/`consolidation`/`episode_candidate`/`profile_candidate`/`session_summary`；可选 `workspace`（须已登记）与 `round`（须存在）。`inputs.pages`/`inputs.notes` 在提交时解析成 `{id,hash}`：页面用当前目录 SHA-256，记忆用活动记录的 `note_hash`；`claims[].evidence` 必须引用已声明输入。`id = hash(content_hash)`，内容相同重放返回既有记录，不写第二条；笔记只是提案，不写 `wiki/`、不写记忆、不调模型。
- `dream-note-list`（只读，续八十二）：按可选 `workspace`/`round`/`status` 过滤笔记，返回 `notes`、`counts.{total,proposed,retained,rejected,applied}`；计数只覆盖过滤后的集合，不泄露其他工作区。
- `dream-note-resolve`（写，续八十二）：把 `proposed` 笔记处理为 `retained`/`rejected`/`applied`。`applied` 必须带 `target {kind:"page"|"memory", id, hash}`：页面 hash 必须等于当前目录 SHA-256，记忆 hash 必须等于活动记录的 `note_hash`，缺失或漂移分别拒绝；`retained`/`rejected` 禁止带 target。同决定+同时刻+同 target 重放，终态后不同请求按 `dream_note_terminal` 拒绝。应用知识仍走 `commit`，应用记忆仍走 `memory-*`。
- `dream-work-open`（写，续二十九）：入参 `round`（open 轮次 id）、`at`、可选 `limit`（1..50，默认 10）。从轮次机会集与轮次绑定的工作区记忆机会生成结构化改进任务（`{id, round, baseline, kind, subject, priority, status, driver, lease_until, created_at, closed_at, result, error}`），按 `(round, kind, subject)` 派生 id 去重；`max_pending=10` 背压（超限 `dream_work_backpressure`）；轮次须仍 open 且其**知识指纹**（排除 state 簿记）与当前一致，否则 `dream_stale_baseline`；引擎内部簿记类 lint（cache/dream_round_stale）不进任务。任务只带结构化字段，不含任何文案模板。
- `dream-work-claim`（写，续二十九）：入参 `id`、`driver`（≤128 字节驱动身份）、`lease_until`、`at`。pending 或租约已过期（`at > lease_until`）的任务可领取/接管；有效租约内他人领取按 `dream_work_lease_held` 拒绝；同参重放回 `replayed:true`；终态任务 `dream_work_terminal`。
- `dream-work-complete`（写，续二十九）：入参 `id`、`driver`、`at`、`result`。仅租约持有者、且租约未过期可完成（`dream_work_not_owner` / `dream_work_lease_expired`）。`result` 只收结构化答案：`judgments`（≤32 项，值为有限数/布尔/≤1024 字节字符串）回答引擎拒绝代判的语义项；`proposals`（≤32 项，`{page,kind,staged_path}`，page 须 wiki/、staged 须 staging/）只引用宿主暂存文件，**引擎绝不写知识页**（应用仍走既有 commit）。完成是终态，重放幂等；同 id 不同结果按 `dream_work_terminal` 拒绝。
- `dream-work-fail`（写，续二十九）：入参 `id`、`driver`、`reason`（≤1024 字节）、`at`；仅持有者可失败，记录终态原因。
- `dream-work-list`（只读，续二十九）：返回任务视图 `{id,round,kind,subject,priority,status,driver,lease_until,created_at,closed_at,result,error}`、`counts`（pending/claimed/done/failed）与 `backpressure`（max_pending/open/at_capacity）。
- `dream-policy`（读/写，续三十一）：读（三个参数都省略）返回 `{policy,default,updated_at}`，缺省 `due_after_seconds=86400`、`min_opportunities=1`、`max_open_rounds=1`。写需 `at`；边界 `0..2592000`/`0..500`/`1..8`，越界/非整数按 `invalid_integer` 拒绝；与现值相同返回 `replayed:true` 零写，否则写 `state/dreams/policy.json` 与 `state/events/dream-policy-*` 事件。
- `dream-due`（只读，续三十一）：宿主 tick 的到期判定。入参 `at`（严格 `YYYY-MM-DDTHH:MM:SSZ` 才做冷却算术）。返回 `{due,reasons[],open_rounds,pending_work,opportunities,last_closed_at,next_due_in_seconds,policy,default,updated_at}`；`due` 需同时满足开轮数 < `max_open_rounds`、机会数 ≥ `min_opportunities`、距最近关闭轮次 ≥ `due_after_seconds`，否则原因记 `open_rounds_capacity`/`insufficient_opportunities`/`cooldown`。只读。
- `dream-retro`（只读，续四十二）：跨轮次经验聚合。返回 `rounds{total,open,retained,rejected}`、`retention_rate`（分母只含 closed 轮次）、`deltas`（8 项 delta 求和）、`drivers[{driver,rounds,retained,rejected,tasks_done,tasks_failed}]`、`work{total,pending,claimed,done,failed}`、`work_by_kind[{kind,count}]`、`last{id,closed_at,decision,delta,drivers}` 与 `fingerprint`；driver/kind 按名称排序，不写记录，供 RSI 复盘与驱动比较。
- `dream-close` 的 retained 门禁（续二十九）：本轮存在 pending/claimed 任务时按 `dream_compat_unresolved` 拒绝——**未被处理的工单不是认可**；`outcome` 另记 `drivers`（本轮实际参与驱动集合，排序去重）供跨驱动经验比较。
- `evo-policy`（读/写，续三十）：唯一在 `enabled=false` 时仍可执行的进化操作。读（`enabled`/`params` 都省略）只读 `state/evo/policy.json`，并只读检查 pending 的 `state/suggestions/*`、`state/overview/*` 状态（人工闸判定，方向 evo→其他模块，零写），返回 `{enabled,params,default,locked,updated_at,pending_human_gate}`；文件缺失返回 23 键默认参数与 `enabled=false`。损坏的 pending 记录按「视为 pending」处理：启用/改参 fail-closed 为 `evo_paused_human_gate:<path>`，而 `enabled=false` 的安全开关不受任何 pending 记录阻断。写必须给 `at`；省略 `params` 时逐字节保留现值，因此 init 后只切开关。参数为封闭 23 键表，仅在 `state.json` 与 `population.json` 都不存在时可写（否则 `evo_policy_locked`），且 params 写要求 `enabled=true`（`evo_policy_disabled_write`）。存在 pending 的 `state/suggestions/*` 或 `state/overview/*` 时，启用或改参按 `evo_paused_human_gate:<path>` 拒绝且零写；只设 `enabled=false` 的安全开关豁免。同值写回 `changed:false,replayed:true` 零写。错误码：`evo_policy_time_invalid`、`evo_policy_locked`、`evo_policy_disabled_write`、`evo_policy_incomplete`、`evo_policy_param_invalid`、`evo_policy_elite_invalid`、`evo_policy_invalid`、`evo_policy_corrupt`、`evo_paused_human_gate`、`missing_field`、`unknown_field`。
- `evo-init`（写，续三十）：入参可选 `seed`（0..4294967295，默认 0）与必填 `at`。按当前策略 `population=N` 一次事务写入 N 条种子基因组（origin=seed、generation=0、Xavier-uniform、精确 binary32）、`population.json`（generation=0、`init={seed,at,policy_hash}`、全部 alive/fitness=null）、`state.json`（空窗与空状态，active=members[0]）与 `evo-init` 事件。`policy_hash = hex_hash(canonical(policy 记录))`。population.init 三要素完全一致时重放 `replayed:true` 零写；任一不同 `evo_already_initialized`；population 存在而 state 缺失 `evo_state_corrupt`。同一 `seed`、策略与 `at` 在独立金库中产生逐字节相同的种子基因组。错误码另含 `evo_disabled`、`evo_seed_invalid`、`evo_paused_human_gate`、`evo_policy_corrupt`、`evo_policy_time_invalid`。
- `evo-observe`（写，续三十/四十一）：快环一步（子系统自监控，不重置主动发言的空闲窗口）。入参 `step`（1..2147483647）、`kind`（social/task/body/novel）、`salience`、`valence`、可选 `outcome`（-1..1 的宿主知识结果，只参与评估、不进入控制器输入）、`body={cpu,memory,latency,budget}`、可选 `subject`（1..64 字节无换行）与 `at`。16 维输入 = 事件 one-hot + salience + valence + 原始 body + 该 subject 的三元关系（无 subject 为 0）+ 上一步 emotion；12 隐层/10 输出走引擎自有 Padé tanh（无 libm）。gain/decay/threshold 均有硬上下限；emotion∈[-1,1]、impulse∈[0,1]。冷却：先检查 `step-last_fire_step<3` 并记一次 blowup，再判 `impulse>=threshold`；首次触发不记违规。窗口环形满后丢最旧，重算 `window_sha256`，body 写回原始请求（非低通）。同一步同业务载荷（不含 at）重放 `replayed:true` 返回逐字节相同结果；同步异载荷 `evo_observe_conflict`；其余乱序 `evo_step_invalid: expected <n>`。非有限中间值 `evo_numeric_invalid` 且不写。错误码另含 `evo_disabled`、`evo_not_initialized`、`evo_kind_invalid`、`evo_subject_invalid`、`evo_subject_limit`、`evo_genome_not_found`、`evo_state_corrupt`、`evo_paused_human_gate`、`evo_policy_time_invalid`。
- `evo-observe-batch`（写，续五十九）：批量快环。入参 `rows`（1..64 个对象数组，每行字段与 `evo-observe` 完全一致）。按顺序在内存中应用各行（含批内重放：重复上一已应用行计 `replays`），单次原子提交 `state.json`；任一行非法（键/值/步序/冲突/上限）整批零写失败关闭。批处理结果与逐条 `evo-observe` **逐字节等价**（e2e 固定）；响应含末行字段 + `applied`/`replays` 计数。错误码 `evo_batch_invalid:rows`/`evo_batch_invalid: count 1..64` 及各行既有码。
- `evo-evaluate`（写，续三十/四十一）：要求窗口长度等于 `policy.window`（否则 `evo_window_incomplete: have=X need=Y`）且 `window_sha256` 与窗口一致（否则 `evo_state_corrupt`）。对全部 alive 成员从中性起点回放整窗：切分为窗口哈希种子的 Fisher-Yates 洗牌后前 70% 训练 / 后 30% 留出（续五十六起不再是时间后缀，同一窗口所有成员同切分、可重放）。评估在轮换场景下进行（续五十八）：`scenario = generation % 4`（0 基线 / 1 身体压力 / 2 事件负偏 / 3 关系对象撤除），变换只作用于评估副本，存储窗口、哈希、切分种子与重放语义不变；响应含 `scenario` 字段。分项：stability、responsiveness（强刺激后的恢复与过冲）、growth（关系信任增量）、novelty（情感轨迹与本批均值的 L1 距离）、energy_cost、impulse_blowups、positive_penalty（用基因输出的情感，不用宿主 valence）、flatness_penalty（情感标准差）、holdout_penalty（训练-留出间隙/0.25）；窗口带非零 `outcome` 时另加 `0.10 × knowledge`（成员情感价态与知识结果的接近度），`breakdown` 回显 `knowledge`/`has_outcome`；旧窗口无 outcome 时该项为 0。lethal 仅由非有限值触发，fitness 恒 -1.0。检查点只在 best 非 lethal 且更优时更新并令 active_genome=checkpoint.genome；检查点记录自身场景 `scenario`（续六十六），回归比较仅在该场景与当代一致时计数（跨场景差为轮换噪声；pre-rotation 无场景检查点门控关闭直至替换）。同窗口同代重放 `replayed:true` 零写。错误码另含 `evo_disabled`、`evo_not_initialized`、`evo_genome_not_found`、`evo_paused_human_gate`、`evo_policy_time_invalid`。
- `evo-evolve`（写，续三十）：前置全部 alive 成员 `evaluated_generation==generation` 且评估窗口未变（`evo_not_evaluated` / `evo_window_changed`），alive<3 为 `evo_population_exhausted`（终态，不无限复活）。回归：checkpoint 存在且 `checkpoint.fitness-best>regression_delta` 时记 `evo-regression` 并累加 streak；达到 `regression_patience` 且 `auto_rollback` 时回滚到检查点，失败谱系按 fitness 降序优先入化石（reason=regression_rollback，上限 `fossil_max_per_gen`），generation 回到 checkpoint 代。正常代：`(fitness desc, genome id asc)` 排名；精英=clamp(floor(alive*elite_ratio),2,alive/2) 原样保留（checkpoint 基因组不在前列时额外加入），protected=clamp(floor(alive*protect_ratio),2,elite_n) 不进入父代池；其余活体与 lethal 进入灭绝集，lethal 优先、其余按 fitness 升序入化石（not_selected）。后代：锦标赛 A/B（k=`tournament`，fitness 大者胜、平局 genome id 小者胜）→ 交叉硬币 → 逐权重 50/50 + 变异硬币与高斯幅度；amplitude=0.10+(mutation_max-0.10)*rank_ratio，δ=g*amplitude/3，权重夹到 [-4,4] 并量化 binary32；移民为全新 Xavier。每代种子=`sha256(seed+":"+from)` 派生 xorshift128。history 记录可为负的 delta；同参重放返回 `last_evolve` 摘要。同一 seed 与同一窗口在独立金库中重放得到相同的 `rng_seed`、化石 id 与后代基因组字节。错误码另含 `evo_disabled`、`evo_not_initialized`、`evo_state_corrupt`、`evo_genome_not_found`、`evo_paused_human_gate`、`evo_policy_time_invalid`。
- `evo-status`（只读，续三十）：`enabled=false` 直接 `evo_disabled`（看开关用 `evo-policy`）。`@vault.verify` 一次后返回策略、代数、种群 size/alive/lethal、检查点、最近评估、最近 delta、历史、窗口容量/已有/步数、化石/灭绝/回归/回滚计数、人工闸与 active_genome/state。未初始化返回 `initialized:false` 与空检查点、零计数。跨记录校验：checkpoint/active_genome 基因组必须存在（`evo_genome_not_found`）、窗口哈希一致（`evo_state_corrupt`）、checkpoint 基因组必须是 alive 成员（`evo_state_corrupt`）、fossil_total/regressions_total/rollbacks_total 与化石文件/事件数一致（`evo_population_corrupt`）。绝不写记录。
- `evo-rollback`（写，续三十）：手动回滚到最佳检查点。checkpoint 为空 `evo_rollback_unavailable`；population 已是该检查点产物且其后未评估/进化时 `evo_rollback_noop`。被丢弃成员按 fitness 降序优先入化石（reason=manual_rollback，上限 `fossil_max_per_gen`），extinct_total 计入全部丢弃数，以检查点基因组重建 N 个成员（slot0 同 id，其余为 origin=checkpoint_clone 的确定性变异克隆），generation=checkpoint 代，rollbacks_total+1，active_genome=checkpoint.genome；广谱种群不复活。同 at 同 reason 重放 `replayed:true` 零写。错误码另含 `evo_disabled`、`evo_not_initialized`、`evo_state_corrupt`、`evo_paused_human_gate`、`evo_policy_time_invalid`。
- `evo-checkpoint`（只读，续三十二）：返回最佳检查点、代际历史、回归/回滚/饱和计数与 `no_improve_streak`；需启用且已初始化，不写记录。
- `evo-fossils`（只读，续三十二）：按 id 排序列出化石（`id/genome/reason/died_generation/fitness/weights_sha256/at`）与计数；`reason` 覆盖 `not_selected/lethal/regression_rollback/manual_rollback`。
- `evo-proactive-due`（只读，续三十三/七十六）：宿主 tick 的主动式判定，仅在 `enabled=true` 且已初始化时可用。返回 `{due,reason,urgency,context,pending,expired,next_in_steps,cooldown_steps,idle,fingerprint}`；`pending` 只计未过期占位，`expired` 计已过租约的 claimed 请求（可被接管，不再阻塞）。`reason` 仅在存在情感冲动时为 `impulse`：冲动 ≥0.55，或冲动网络在上一次主动请求之后越过过阈值（尚未表达的冲动）；**效价单独不构成理由**，否则空串。`due` 需要同时满足：没有 pending/claimed 请求、距最近一次主动请求 ≥ `cooldown_steps=8` 观察步、且**距最近一次可观察的 agent 主体活动 ≥ 1800 秒**（`idle.required_seconds`）。`idle={ok,seconds_since_activity,required_seconds,last_activity_at}` 如实报告空闲窗口；`last_activity_at` 为空（旧状态无活动戳）时失败关闭、不主动发言。`context` 只含结构化状态（步数/情感/冲动/身体/关系/窗口哈希/基因组），不含自然语言。只读。
- `evo-activity`（写，续七十六）：宿主上报 agent 主体的活动（用户轮次、主 agent 正在处理请求等），用于主动发言的空闲门。入参仅 `at`。记录单调：只有晚于当前 `last_activity_at` 的时间戳会写入 `evo/state.json`，较旧或相同时间戳零写重放并回报当前值（`replayed:true`）；响应 `{reported,replayed,last_activity_at,fingerprint}`。`evo-observe`/`evo-observe-batch` 是子系统自监控，**不重置**空闲窗口；`evo-thread-append role=user` 与 `evo-proactive-followup`（用户回复）在同一事务内视为活动。宿主可用一个随时被主 agent 触碰的 presence 文件驱动上报：守护进程 `--activity-file` 读取文件内显式 UTC 时间戳（缺省用 mtime）后调用本 op。
- `evo-proactive-open`（写，续三十三）：把当前判定落成一条请求。入参 `driver`（1..64 字节无换行）、`lease_until`（严格时间且晚于 `at`）、`at`。原子认领：有未过期 pending/claimed 请求时 `evo_proactive_backpressure`，未到期 `evo_proactive_not_due`；若存在过期 claimed 请求则**接管**该请求（同一 id、更新 driver/lease、写 `evo-proactive-reclaim` 事件，返回 `reclaimed:true`），不重复创建。记录写 `state/evo/proactive/<id>.json`（id 绑定 `step+genome+window_sha256`），初始 `status=claimed`，并写 `evo-proactive-open` 事件。返回 `{id,step,reason,urgency,context,driver,lease_until,fingerprint}`。**核心不调用模型**；请求是给宿主驱动的结构化 token。
- `evo-proactive-complete`（写，续三十三）：宿主驱动完成请求。入参 `id`、`driver`、`at`、`result={text,model}`（text ≤8192 字节且无 `\r`；model 1..128 字节无换行）。仅持有者可完成（`evo_proactive_not_owner`），租约过期 `evo_proactive_lease_expired`，非 claimed 终态 `evo_proactive_terminal`。同 id 同驱动同 at 同 result 重放 `replayed:true` 零写；写 `evo-proactive-complete` 事件。
- `evo-proactive-fail`（写，续三十三）：持有者记录失败。入参 `id`、`driver`、`reason`（1..1024 字节无换行）、`at`；仅 claimed 态可由持有者置为 failed，重放语义同上，写 `evo-proactive-fail` 事件。
- `evo-proactive-ack`（写，续三十五）：宿主在**真正投递**后确认送达。入参 `id`、`at`。仅 `status=done` 可确认（否则 `evo_proactive_not_deliverable`）；`at` 不得早于 `closed_at`（`evo_proactive_ack_time_invalid`）；同 `at` 重放 `replayed:true` 零写，已送达后再以不同 `at` 确认按 `evo_proactive_already_delivered` 拒绝，避免重复投递。记录新增可选 `delivered_at`（旧记录缺失视为未送达），写 `evo-proactive-ack` 事件。
- `evo-proactive-followup`（写，续五十一）：用户回复已投递的主动消息后创建同链跟进。入参 `id`（父）、`user_text`（1..4096 字节无 `\r`）、`driver`、`lease_until`、`at`。父必须 `done` 且已送达（否则 `evo_proactive_parent_not_delivered`）；链深 `turn+1` 不得超过 8（`evo_proactive_followup_depth`）；存在 pending/claimed 时 `evo_proactive_backpressure`。跟进绕过情感 `due` 门禁，但不绕投递、在飞背压与深度三道门；用户回复视为 agent 主体活动，在同一事务内推进 `last_activity_at`；记录新增 `parent/turn/user_text`，写 `evo-proactive-followup` 身份事件。
- `evo-proactive-list`（只读，续三十三）：按 id 排序列出请求视图 `{id,step,reason,urgency,status,driver,lease_until,created_at,closed_at,delivered_at,result,error}` 与 `counts`（pending/claimed/done/failed/delivered/undelivered）；`done` 为已完成总数，`delivered`/`undelivered` 按 `delivered_at` 区分；不写记录。
- `evo-expression`（只读，续三十九）：入参 `at`。返回结构化拟人化表达帧 `{posture,emotion,emotion_label,prosody{rate,pitch,volume},gesture,expression,will_initiate,reason,next_in_steps,impulse,energy,pending,expired,fingerprint}`。`will_initiate` 复用主动式闸门（阈值/冷却/未过期占位）；仅输出 token，不生成文案；不写记录。
- `evo-thread-open`（写，续五十五）：入参 `proactive`、`text`、`driver`、`at`。父请求必须 `done`（否则 `evo_thread_parent_not_done`）且已送达（否则 `evo_thread_parent_not_delivered`）；同 `(proactive,at)` 重放零写，同 id 不同载荷 `evo_thread_already_open`。记录写 `state/evo/threads/<id>.json`（id 绑定 proactive+at），首轮 agent，`max_turns=16`，写 `evo-thread-open` 事件。
- `evo-thread-append`（写）：入参 `id`、`role`（agent/user）、`text`（1..4096 字节无 `\r`）、`at`。仅 open 线程；同轮同 at 重放零写；`turns` 达 `max_turns` 拒绝 `evo_thread_turn_limit`；写 `evo-thread-append` 事件。`role=user` 表示用户在场，同一事务内推进 `last_activity_at`（agent 轮次不推进）。
- `evo-thread-close`（写）：入参 `id`、`at`；open→closed，同 at 重放零写，closed 再关 `evo_thread_terminal`；写 `evo-thread-close` 事件。
- `evo-thread-list`（只读）：`threads[{id,status,turns,max_turns,last_proactive,updated_at}]` 与 counts（open/closed）；不写记录。
- `context` 接线：`textual=false` 且存在匹配**当前** digest 的注册 sidecar 时，`source_text` 即 sidecar 正文、`extraction_required:false`、`extraction:{kind, extractor, version, bound_sha256, source_sha256}`（`bound_sha256` 为记录内哈希，`source_sha256` 为工单当前 digest）。查找只经目录注册条目，绝不裸读路径——宿主直写的未注册文件不会成为文本源。来源被 `forget`/撤销或字节漂移（重 `scan` 后 digest 变化）时 sidecar 不再命中：`context` 回到 `extraction_required:true` + `source_text:null`，`lint` 对旧 sidecar 报 `extraction_source_stale`（撤销/缺失）或 `extraction_source_drift`（字节已变）。OOXML/HTML 优先走引擎自抽通道，不受 sidecar 影响。native 宿主在 `scan`/`refresh` 导入 PDF/图片时即按上述 sidecar 契约自动执行本地 OCR/PDF 适配器；若导入阶段未成功，`context` 发现 `extraction_required:true` 时还会再兜底重试并重新返回 `source_text`；适配器返回值必须与工单 `source_hash` 一致，任何失败都回退到未抽取响应，不写半成品。`read-source` 不变：登记字节通道与抽取投影通道分离。
- sidecar 按**内容寻址**：文件名是字节哈希，因此两条相同字节的不同路径共用同一条 sidecar（provenance 记录在记录自身的 `source` 字段，指向首次入账路径）。接受这一语义并如实入账，是内容绑定失效（drift ⇒ 不再命中）能够单点成立的前提。

选型背景：宿主侧 OCR 适配器的调研（PP-OCRv6_small ONNX，约 20MB 级）见 `specs/engine/tasks.md` 续十一/十二落账；核心边界不因该通道改变；nativehost 的 OCR 例外与回退见 `docs/ocr.md`。

`index.mbt.md` 和 `views/*.mbt.md` 的目录/视图 IR 来自第一个 `mbt check` 代码块；后续 `mbt`/`mbt check` 块由 MoonBit 一起编译，可提供共享辅助定义和测试，但不改变引擎提取的 IR。代码块外的 Markdown 是可编辑说明，会被编译器忽略但仍随源文件保存。解析器统一接受 LF/CRLF，避免 Windows 编辑器产生的换行差异造成编译器与运行期分叉。首块内非字面量、不闭合代码块和不规范声明会拒绝；首个受检块闭合围栏之后的任何内容都必须以空行分隔（下一个字符为换行或文件结束）；紧跟围栏的裸文本按畸形 Markdown 拒绝（目录返回 `catalog_literate_tail`，视图返回 `view_literate_tail`，修复指引是补一个空行），不会静默当成无关注释；后续块的语法/类型由 `moon check` 拒绝。引擎提交或缓存重建只替换首个规范 IR 块，保留前后 Markdown 和辅助块；这些说明和辅助块不参与目录指纹。

工单依次进入 `pending → context-ready → analysis-done → committed`，终止也可为 `cancelled`。同一 vault 同时只允许一个非终态工单进入分析。`context` 提供研究目标、原始来源及既有页面全文/哈希，避免覆盖式重写。上下文变化会要求重新分析。分析里的 `conflicts` 在提交时变成持久化审核项。

`context` 的页面正文默认按范围展开（`scope=related`，续七十二）：先取引用该来源的页面，再取与来源同一命名空间（`raw/<仓库>`）的页面，按页面 ID 稳定排序，最多 64 页；响应始终带完整 `page_hashes`（失效判定不受截断影响），并报告 `pages_total` 与 `pages_omitted`。需要整库综合时显式传 `scope=all`；未知 scope 报 `context_scope_invalid`，不会静默退化成全量。全局知识库下这是每个工单成本的闸门：响应体积不再随页面总数线性增长。

`context` 还返回 `context_token` 和稳定的 `source_summary_id`。自动宿主应在 `analysis-submit`、`draft-submit`、`commit` 中回传该 token；它固定所有来源/页面/目标的登记版本与失效状态，拒绝模型调用期间的变动或被另一客户端刷新的旧上下文。分析和提交的旧式手工调用可以省略 token。已提交工单的 `commit` 重放不重新发布内容。

工单记录新增 `context_version`；旧记录缺失时按空串读取，下一次 `context` 会刷新版本并要求重新分析，避免沿用没有完整元数据基线的旧分析。

`draft-submit` 接收 `order`、必填 `context_token` 及 1..32 项 `pages`。每项精确为 `{id,kind,title,sources,tags,body}`；所有字段必填，`sources/tags` 为字符串数组，`body` 不含 frontmatter。引擎生成规范 frontmatter，保留已有页路径或为新页派生 `wiki/<id>.md`，校验来源/互链/上下文后才写入 `staging/<order>/generated/<hash>.md`。批次文本上限 1 MiB，整批校验失败不写草稿；成功返回可传给 `commit` 的 `pages` 清单和 `published:false`，不改变权威目录。模型不能指定路径或跳过正式编译提交。

Agent 写入 `staging/<order>/page.md` 后提交：

```json
{"op":"commit","vault":"/absolute/my-vault","order":"...","at":"2026-10-16","pages":[{"id":"concepts/example","path":"wiki/concepts/example.md","staged":"staging/.../page.md"}]}
```

页面前导只支持 `type`、`title`、`sources`、`tags`。字符串支持 JSON 双引号和 YAML 单引号；数组支持 JSON/YAML inline list 或 YAML block list，但未知字段和复杂 YAML 结构仍拒绝。页面类型为 `entity` / `concept` / `source-summary` / `synthesis` / `query`。来源必须包含当前工单原件；未失效页面的所有来源和 wikilink 必须有效。

```markdown
---
type: concept
title: 示例
sources: ["raw/example.md"]
tags: ["研究"]
---
正文与 [[concepts/another|其他页面]]。
```

链接以稳定 id 定位；支持显示别名和标题锚点（`[[page#标题|跳转]]`）。锚点只影响视觉路由，目录依赖仍只记录页面 id；片段必须非空、不能含第二个 `#` 或换行，渲染器按标题 slug 定位并在刷新后滚动。代码围栏与简单行内代码中的链接不参与依赖检查。`[[x|待建]]` 仍然要求 x 存在。

没有提交 source-summary 时，引擎生成一页明确标为“未生成语义摘要”的来源元数据页；不会把分析字段当作已核实的总结。已提交工单重试不重复记账。提交和取消后保留 staging 草稿供检查；当前没有自动清理策略。

## 外部编辑、恢复与缓存

`scan` 登记原件版本变化、取消过时工单并传播失效；native 宿主在此按导入的 PDF/图片工单入账 OCR sidecar 时，返回的 `fingerprint` 是入账后的当前指纹。遇到未登记的知识页修改会拒绝。`refresh` 显式登记已注册页面和 purpose.md 的人类编辑，校验来源及互链后重建缓存；暂不自动登记新建的未注册知识页。

`python3 scripts/watch.py /absolute/my-vault` 持续监听，`--once` 执行一次。存在默认视觉声明时同时重新编译视图；可用 `--view views/custom.mbt.md` 选择另一份视觉源。失败时顶层响应为 `ok:false`、退出码非零，并保留上次 HTML；下一次文件变化继续尝试。监听只负责发现变化，校验与发布由 MoonBit 执行。

提交先验证拟发布内容，再编译候选目录，重新检查来源/基线，然后写入 `state/transactions/pending.json`。正文和状态写入后，根目录最后发布。恢复按根目录的旧/新版本回滚或前滚；成功恢复会先把方向和原始 journal 写入内容寻址的 `state/transactions/history/<sha256>.json`，再移除 pending 日志，重复恢复保持幂等，历史内容冲突则保留 pending 并拒绝继续。发现外部编辑会保留日志并报冲突，不猜测覆盖。对外部编辑器而言，这不是多个文件的瞬时快照原子性。

`state/orders`、`state/reviews`、`state/research`、`state/suggestions`、`state/overview`、`state/evidence`、`state/memory/<workspace>`、`state/workspaces`、`state/dreams`、`state/dream-work`、`state/dream-notes`、`state/impacts`、`state/providers`、`state/provider-jobs`、`state/events` 以及 `state/transactions/history` 为权威记录；`state/transactions/pending.json` 是进行中的恢复日志；`.corridor/` 可整目录删除。`status` 会验证权威声明/正文并报告 `index_cache:valid` 或 `missing_or_invalid`，但不自动重建；`rebuild` 恢复缓存，`verify` 检查缓存缺失或损坏；`search` 可按需重建。缓存含算法版本、输入指纹及内容校验，不能替代文件版本检查。

`memory-candidates`（只读，续八十二）必须显式 `now`：列出记忆整合候选而不做决定。`merge` 给同 token 不同字节的近重复组（`duplicate`/`keeper`/`reason:"similar_text"`，keeper 是组内 id 较小者）；`prune` 先按三层分类（pinned 或 importance≥0.8 或 layer=episode 为 core，永不提名；importance≥0.5 或情感强度≥0.5 为 important，慢衰减；其余 normal，快衰减），仅当强度低于该层阈值时提名，返回 `tier/importance/decay/strength/score/age_days` 与 `never_used`/`decayed` reason；顶层 `tiers` 给出 active 各层计数。冲突中的笔记两项都不提名；来源失效或漂移的需要 `memory-supersede` 而非删除，不提名为 prune；已参与 merge 的笔记不再提名 prune；已 supersede/archive 的是历史。只读，不写 vault，也不返回 `execution:"host_required"`；引擎不自动删除或归档。
与 `memory-prefetch(dedup:"similar")` 共用 `@index.similar_eligible/similar_tokens/similar_merge`，两个面对同一对笔记给出一致答案；差别只是本 op 不需要种子。只读，不写 vault，也不返回 `execution:"host_required"`。
`lint` 是只读诊断入口，允许在目录或内容损坏时运行，不替代 `verify` 的硬失败门禁。它在能解析文学化目录时继续检查目录语义、raw 来源哈希、页面正文哈希、页面 frontmatter、来源/互链、state/vector/evidence/memory/impact 记录和 `.corridor/fts.json`；evidence 还会报告正文 UTF-8 锚点漂移、精确 raw 锚点漂移、引用页面无法解析的记录（`evidence_reference_unresolvable`），以及页面/来源撤销造成的陈旧状态；impact 额外报告 `impact_subject_missing` 与 `impact_no_drift`；memory 额外报告来源撤销或漂移造成的 `memory_source_stale`，单条记录无法表达的跨记录不变量（`memory_supersede_origin_missing`、`memory_supersede_target_missing`、`memory_supersede_link_asymmetric`、`memory_duplicate_note`、`memory_key_ambiguous`），以及 warning 级 `memory_conflict`，另以 `memory_time_inverted` 报告 `updated_at`/`archived_at` 早于 `created_at` 的倒序时间戳。无法解析时至少报告目录语法问题，并尝试报告文学化编译问题。响应含 `status`、`errors`、`warnings`、`violations` 和兼容的 `stale` 字段；每条诊断固定包含 `predicate`、`subject`、`path`、`detail`、`fix`、`severity`，按这些字段稳定排序。`lint` 不写入 vault，也不把 warning 当作 `verify` 成功。

`state/events/` 只接受引擎已定义的事件操作；未知 `op` 会被 `verify`/`lint` 拒绝，不会被当作可保留的扩展事件。每个已知 `op` 还使用固定的顶层字段集合并检查必填字段、哈希、路径、时间、数组和嵌套空间；未知字段、缺少必填字段或不匹配内容寻址文件名同样拒绝。provider job、导入、建议、质量审核、证据、provider 注册、审核决议、研究、摄入等可由事件字段确定文件名的操作会核对完整路径；`refresh`/`forget` 等路径还依赖提交前后的全量 vault 指纹，仍通过字段和事务基线校验。事件字段按实际操作包括 provider job 生命周期、导入、目标/综述建议、质量审核、证据提交/替换、provider 注册、刷新、审核决议、研究工单、摄入和来源撤销。

目录损坏时，`read-last-valid` 可显式读取缓存的上次有效目录与正文，响应标记只读快照；所有引用仍重新核验，不能用旧目录掩盖正文漂移。缓存也被删掉时需先修复权威目录。

`forget` 保留原件与撤销标记，使依赖页和沿互链传播的页面失效并退出搜索。原件内容不变不会被 scan 自动复活；这不是备份或原件的物理擦除。`scan` 发现 raw 文件物理删除时也保留 stale 来源条目，并写入内容寻址的 `state/events/source-missing-*.json`；重复扫描不会重复记账，文件以新哈希重新出现时会创建新的来源版本和工单。

`archive-page` 接收页面 `id`、`at` 和人类 `reason`，在一次事务中将页面标记为失效、传播互链依赖、写入 `state/events/page-archive-*.json` 并刷新目录/日志；正文文件和来源原件保留。相同请求重放先与目录现状对账：页面仍处失效态才返回 `replayed`，页面已被恢复后再重放同一请求按 `page_not_active` 拒绝，已失效页面同样拒绝新的归档请求。`restore-page` 只能恢复存在归档事件、正文哈希未变且所有来源仍有效的页面，并重新执行互链校验；来源已撤销或正文漂移时拒绝恢复。来源字节被整体替换并经 `refresh` 重新登记后，恢复会比对发布时 ingest 事件→工单记录的来源哈希与当前 raw 条目，不一致按 `restore_source_changed` 拒绝并指引重新摄入。恢复解除目标页失效的同时，把仅因传播而失效的依赖页一并复活（自身带归档事件的显式归档、来源已撤销或正文漂移的页面除外），响应以 `reactivated` 列出；互链成环的两侧因此可在恢复任一侧后同时回到活跃态。恢复事件同样持久化；页面再次归档后重放旧恢复请求按 `page_restore_stale` 拒绝，需换新时间戳。

## 检索、图与维护

- `search` 是分块级 BM25 的页面视图（续七十三）：页面按约 800 字/重叠 80 切块建索引，命中块归并到页面（每页取最高分块），返回 `{id,title,score,excerpt}`；缓存为 `.corridor/fts.json` v5（`chunk-hybrid-v1`）加旁车 `.corridor/fts.vectors.bin`：主文件含版本/算法/目录指纹/页面绑定/块表/序列化 BM25，旁车是逐块 256 维 f32 原始小端字节，主文件用 `vectors_sha256` 钉住旁车字节；绑定派生时的页面哈希，算法、页面或任一文件不匹配即重建。单文件仍受 16 MiB 写入上限约束，超限的库不再让查询失败：本次进程内保留集合继续服务（`cache_rebuilt:true`），`lint` 以 `cache_invalid: file_too_large` 如实报告，下次进程重建。可选 `query_vector:{space:{id,dimensions},values}` 或 `query_vector:{space,values_b64}`，以 RRF 融合关键词与暴力余弦结果。`values_b64` 是 RFC 4648 Base64 的 binary32 little-endian 字节，长度必须为 `dimensions*4`；`values` 与 `values_b64` 二选一。宿主也可提交 `vector_candidates:{space,hits:[{id,score}]}` 覆盖本次查询的本地暴力扫描，并用可选 `provider` 绑定 active search provider；引擎会校验空间、活跃页面、重复 id、有限分数和最多 100 个候选，再按候选顺序参与融合。两种向量输入互斥。命中后按图边权（互链 3.0、共同来源 4.0）除以跳跃距离打分，最多 `hops` 跳补入上下文候选并按分数降序、同分按 id 排序；`hits` 本身仍是关键词/向量排名。`embedding-submit` 接收 `{space,items:[{page,sha256,values|values_b64}]}`，可选 `provider` 绑定 active embedding provider；不同空间及旧页面向量隔离。没有模型向量或外部候选时只走关键词。关键词缓存标记为 `chunk-hybrid-v1`，算法变化会使旧缓存失效并重建。
- `embedding-plan` 接收 `{space,limit?,provider?}`，按页面 id 排序返回缺失或旧版本的活跃页面向量任务；provider 存在时必须已注册且空间/能力匹配。批次默认 8、范围 1–128。结果含 `items:[{page,sha256,text,truncated}]`、`remaining`、`text_recipe` 与目录指纹。文本采用 `title-body-prefix16KiB-v1`，保留标题与正文的完整字符 UTF-8 前缀，最多 16 KiB；正文原件和关键词索引不截断。宿主应把文本配方计入空间 id，调用外部模型后经 `embedding-submit` 发布。无向量任务时不写入状态。当 provider 声明 `embed-multimodal` 能力时，该 provider+空间的路由改发图片任务：item 为 `{page,sha256,modality:"image",image,image_sha256}`，`image` 是该页来源集合中按 id 排序的第一个活跃图片 raw（配方 `first-image-source-v1`，`image_sha256` 钉住字节版本），响应中 `image_recipe` 与 `text_recipe` 恰有一个非空；没有图片来源的页面在视觉空间中结构性跳过，不计入 `remaining`。多模态向量经 `embedding-submit` 同步通道发布（同 extraction sidecar 先例）；provider-job 信封当前只接受文本配方，图片 item 在 `@base.keys` 处明确拒绝。
- `retrieve`（续七十三，续八十四扩展系统向量）返回分块级命中：`{hits:[{chunk,page,title,score,text,text_source,lanes:{text_rank,vector_rank}}],lanes:{text,vector,reason,vector_space},fingerprint,cache_rebuilt}`，`chunk` 形如 `<页面ID>#<块序号>`，可选 `limit`（1..100，默认 20）与 `namespace=raw/<仓库>`（只保留来源落在该前缀下的页面，非法值报 `retrieve_namespace_invalid`）。可选 `query_vector:{space,values|values_b64}` + `provider`：引擎校验 provider 已注册且类型/空间/能力匹配、查询向量形状与活跃页面向量后，向量路切换为 `vector:"system"`、`reason:"provider_vectors"`，每个命中的页面按宿主排名映射到首块 `<page>#0`；`lanes.vector_space` 回显实际空间，无可用页面向量时为 `vector:"system"`/`reason:"no_matching_vectors"`。`query_vector` 缺 `provider` 时报 `missing_field: provider`，显式 null 报 `retrieve_provider_required`——系统路必须可追溯到已注册 provider。未提供 `query_vector` 时如实回退 `vector:"algo"`/`reason:"no_system_engine"`——算法路是字符 2/3 元组 + 拉丁词元的哈希特征（256 维、L2 归一化、精确扫描），固定 k=60 的 RRF；它不分语种、不做语义互译。系统向量由宿主生成并承担模型成本/许可，核心不调用 OS 框架或网络，也不静默降级。命中块的 `text_source` 说明正文来自命中块（`chunk`）还是页面摘录（`page`，仅向量路命中且文本路未命中时）。同一内核将来用于记忆集合，隔离靠集合与目录而不是查询过滤。

- `provider-register` 持久化 provider 名称、`embedding`/`search` 类型、能力、空间和 `memorycorridor-provider-v1` 协议；能力是封闭词表 `embed`/`search`/`embed-multimodal`，未知能力按 `provider_capability_unknown` 拒绝（AGENTS 不支持能力明确拒绝），`embedding` 类型必须含 `embed`、`search` 类型必须含 `search`；重放按注册身份（provider/kind/空间/能力/协议/registered_at）比对，心跳改写的 `last_seen` 与撤销改写的 `status` 不影响幂等窗口，重放响应回显当前 `status`（revoked 即回显 revoked），不同配置拒绝。`provider-heartbeat` 更新 active provider 的 `last_seen`，`provider-unregister` 标记 revoked 并保留事件。`provider-job-open` 创建带输入摘要和幂等键的 pending 执行信封，并绑定当前活跃页面版本；embedding 任务还必须原样携带 `embedding-plan` 生成的文本和截断标记。宿主先用 `provider-job-claim(id, worker, lease_until, at)` 原子领取任务，再用 `provider-job-heartbeat` 续租；有效租约内只有同一 worker 能完成或取消，过期领取可被新 worker 接管。`provider-job-complete`、`provider-job-cancel` 或 `provider-job-fail` 关闭它；领取者可以在租约过期后用 fail 明确记录超时。provider 撤销后 `provider-job-cancel` 与 `provider-job-fail` 仍可用（取消滞留任务），`provider-job-complete` 因结果归属需要 provider 在册而被拒。失败原因可记录超时、进程错误或协议错误，所有终态可重放且不能交叉覆盖；complete 的重放以首次关闭时记录的 `result_hash` 校验负载，携带不同结果的同键重试按 `provider_job_terminal` 拒绝。embedding job 的完成结果会在同一事务中校验并写入 `vectors/`；search job 的完成结果会校验空间、活跃页面、分数和重复项后保存。记录位于 `state/providers/` 和 `state/provider-jobs/`，参与目录指纹、事务恢复和 pack。引擎只管理生命周期、任务状态、租约和载荷校验，实际进程启动、推理、流式调度和模型成本仍由宿主负责。
- `EmbeddingProvider` 与 `VectorSearchBackend` 为独立 MoonBit 回调接口。嵌入式宿主可替换；CLI/MCP 接收数据，不接收可执行回调，也不调用模型或网络。
- `search.result.hits[].excerpt` 最多 360 UTF-8 字节，按不同查询词覆盖数选择段落；长段落定位最长匹配词附近，同分取较早段落。无词匹配（包括纯向量查询）取正文前缀。保留完整 Unicode 字符；排名规则不变。
- `search.result.context` 提供来源、路径、页面哈希、截断标记和该页的 `evidence` sidecar（含逐项 `valid` 与 UTF-8 区间）；`budget` 1..65536，按引用与正文的 UTF-8 字节总和保守计量；不是特定模型的精确 token 数，也不计 JSON 元数据。先装配排名候选，再补最多 2 跳图邻居。`spread` 默认 `ranked`：尚有候选时为当前页分配剩余预算的一半，至少容纳引用与一个 Unicode 字符；末页可用余额，短页释放余额。`spread:"even"` 改为按剩余候选均分剩余预算（同样至少容纳引用与一个 Unicode 字符），紧凑预算下覆盖更多排名页但每页更少。
- 上下文使用同一查询定位规则，`body_start/body_end` 为解析后 `Page.body` 的 UTF-8 半开区间，`offset_unit:"body_utf8_bytes"`；从页面正文按该区间截取即可重建引用后的文本。它不是 frontmatter、UTF-16 或原文件字节位置。`used` 精确等于所有块 `text` 的 UTF-8 字节数。响应另返回启发式 `estimated_tokens`（`estimate_recipe:"cjk_char_latin_word_v1"`：CJK/假名/谚文字符各 1、拉丁/数字词各 1，标点空白不计）、每块 `estimated_tokens` 和顶层 `truncated`（任一块未装完整正文）；它用于宿主成本核算，不是特定模型 tokenizer 的精确值，也不改变以 UTF-8 字节为单位的预算语义。
- 完整正文逐字相同的候选只装配一次；块内 `duplicates` 保留其他页的 `{id,path,sha256,sources,origin}`。部分逐字相同的段落从后续正文选择中排除，重复项同时出现在顶层和块内 `paragraph_duplicates`，包含页面、段落哈希、`paragraph_start/end` UTF-8 区间、来源和命中类型。各页版本独立，不合并为主页面来源。默认 `dedup:"exact"` 只做逐字合并，不做语义近似判断；显式 `dedup:"similar"` 额外把**分词序列完全相同且两侧各 ≥64 UTF-8 字节**的正文/段落合并（大小写、空白、标点等排版差异可以命中；改变任意字母、数字或 CJK 字符、词序或增删内容都不会命中），合并项记入 `similar_duplicates`/`similar_paragraph_duplicates`（含 `similarity:1` 和段落 `keeper_id`），被合并页的版本与来源独立保留。这是确定性的词典级近似，不是模型语义判断。`strategy` 标识实际规则：默认 `ranked_halves_exact_body_paragraph_v1`；opt-in 组合为 `<exact|similar>_body_paragraph_<ranked|even>_v2`。来源/正文变化与失效仍在装配前核验。见 [检索上下文规格](../specs/engine/retrieval-context.md)。
- `graph` 输出互链有向边与共享来源边（权重分别为 3.0 和 4.0，与检索扩展共用同一强度定义）；`neighbors` / `path` 探索时按无向图遍历。`weighted-path` 把边权作为路径代价计算确定性最短无向路径（互链 3 比共同来源 4 更便宜，权重相同按页面 id 解 tie）。`tree` 返回可直接消费的层级树 `{name,dirs[],pages[]}`，根节点名为 `wiki`；目录按名称排序，页面按 `index` 优先、名称和 id 排序，并保留 `id/title/path/kind/stale`。来源撤销后的页面仍出现在树中并标记 `stale:true`。`insights` 给出孤儿、跨类型连接、稀疏标签、确定性连通分量、节点 degree/weighted_degree、edge_kinds，以及基于边权和稳定标签 tie-break 的 `communities:[{id,members,weight}]`；社区分析是可解释的加权标签传播启发式，不宣称语义聚类或模型质量。
- `quality-audit` 接收显式 `at`，在当前已验证图快照上把孤儿页、稀疏标签、已登记但没有活跃知识页依赖的 raw（`unreferenced_source`）、仅有 legacy raw 锚点的页面（`legacy_evidence_anchor`）、raw 原文锚点漂移/撤销/无法核验的页面（`invalid_evidence_anchor`）、已有有效 claim 但正文覆盖不完整的页面，以及没有有效事实证据的 entity/concept/synthesis 页面转为持久 `state/reviews/` HumanGate 债务；每条审核记录保存 `predicate/subject/page/source/input_fingerprint`，`review-list` 额外返回 `input_status`（`current`/`stale`/`unknown`），让历史决议与当前输入变化可区分。它不阻塞结构提交，按 raw/purpose/page/evidence 输入指纹内容寻址并支持相同请求重放。响应的 `fingerprint` 在首跑与重放两条路径上都是当前目录指纹（可直接比较两次运行），审核所冻结的输入快照另以 `input_fingerprint` 暴露。source-summary 兜底页不要求语义证据或覆盖报告。审核仍通过 `review-resolve` 由宿主或人类决定。
- `research-topic` 接收主题、1..16 个查询、显式时间和可选幂等键，写入 `state/research/<hash>.json` 并追加事件；相同键和相同内容重试返回 `replayed`，同键不同内容拒绝。它只生成宿主执行队列，不联网、不调用模型；宿主完成外部检索后把结果写入 `raw/`，再调用 `scan`。`research-complete` 只接受已登记且仍有效的 raw 路径并将工单置为 `completed`；`research-cancel` 关闭未完成工单；两种终态转移均追加事件并支持相同请求重放。
- `purpose-suggest` 冻结当前 `purpose.md` 哈希、vault 基线、图和洞察，写入 `state/suggestions/<hash>.json`；外部宿主据此生成建议，人类确认后调用 `purpose-apply`。应用前必须同时匹配目标哈希和去除建议自身记录后的上下文基线，更新与事件在同一事务中发布；目标发生外部变化时拒绝，避免覆盖人类编辑。
- `overview-suggest` 冻结 purpose 哈希、所有活跃知识页哈希、vault 基线、图和洞察，写入 `state/overview/<hash>.json`；外部宿主提交完整 `synthesis` Markdown 到 `overview-apply`。页面来源必须是当前有效 raw，wikilink 必须通过常规页面校验，更新 `wiki/overview.md`、目录视图、建议状态和事件在同一事务中发布。`status/stats` 根据冻结输入报告 `missing`、`pending`、`current` 或 `stale`。
- `evidence-submit` 接收 `page`、当前页面 `page_hash`，以及 `items` 数组内的 1..128 个 `{source,body_start,body_end,quote}`（`source_start`/`source_end`/`source_quote` 可选）。每个来源必须是当前有效 raw；同一来源可以提供多个独立正文区间，但完全重复的 claim 会被拒绝。范围是解析后 `Page.body` 的 UTF-8 字节半开区间，必须满足 `utf8_slice(body,start,end)==quote`。可选的 `source_start/source_end/source_quote` 三字段会进一步要求 `utf8_slice(raw_text,source_start,source_end)==source_quote`，并在返回中标记 `source_quote_verified:true`；省略时兼容旧记录但不宣称原文区间已核验。返回的 `source_anchor` 将 provenance 强度明确标为 `exact`、`legacy` 或 `invalid`，不代表语义蕴含。记录按内容寻址写入 `state/evidence/<sha256>.json`，同时追加事件；相同内容重试返回 `replayed`。`evidence-list` 和 `read-page.evidence` 返回证据及逐项 `valid`，页面版本、正文范围、来源原文漂移或来源撤销后保留记录但显式标记失效。`status/stats` 返回证据记录的 `records/valid/invalid` 以及 exact/legacy/invalid raw 锚点计数。
- `evidence-replace` 接收相同页面和 claims 字段以及旧证据 id `previous`。新记录必须通过 exact/legacy raw 校验；旧记录页面版本必须一致且未被替换。引擎在同一事务中写入新内容寻址记录、`evidence-replace` 事件，并给旧记录加 `superseded_by`。旧 JSON 永久保留用于审计和 pack，但当前 `evidence-list`、检索来源和覆盖统计只计算未被替换的记录；相同请求幂等重放，旧记录或页面版本不匹配会拒绝。
- `workspace-open`（续七十五）登记工作区，是记忆按工作区隔离的锚点：`path` 必须是宿主已规范化的绝对路径，引擎不再解析符号链接或 `..`，含 `.`/`..` 段、双斜杠、尾斜杠、换行或空串一律 `workspace_path_invalid` 拒绝；`id = sha256("workspace-v1\n" + path)` 内容寻址，同一路径永远映射到 `state/workspaces/<id>.json`（`{version,id,path,created_at,last_opened_at}`，闭字段校验且 `last_opened_at >= created_at`）。同一 `at` 重放零写并回 `replayed:true`；较新的 `at` 只刷新 `last_opened_at`；较早的 `at` 按 `workspace_time_order` 拒绝，不回退时间。`workspace-list` 只读，按路径、再按 id 稳定排序，返回 `{workspaces,count}`。登记记录参与目录指纹、事务恢复与 pack。
- `workspace-wiki-plan`（只读，续八十二）：给定已登记 `workspace`，按可选 `namespace`（`raw/<namespace>/` 前缀）、显式 `pages` 与一跳共享来源页选出工作区 wiki 投影。返回 `pages`（id/path/kind/sha256/sources/source_hashes/stale/explicit/shared）、`claims`、`manifest`、`index_text` 与 `fingerprint`。它不写任何文件、不新增目录条目、不改变指纹；`workspaces/<id>/wiki`、`claims`、`manifest.json` 与 `workspaces/index.mbt.md` 由宿主脚本 `scripts/workspace_wiki.py` 写出，删除后可重建。
- `memory-submit` 记录终身记忆笔记：`kind` 取 `preference`/`decision`/`constraint`/`fact`/`goal`，`workspace` 必填且必须已由 `workspace-open` 登记（否则 `memory_workspace_unknown`），`scope` 仅接受 `project` 或 `session`：前者在该工作区内长期可见，后者仅在调用方显式给出相同 `session` 时可见；`scope=session` 必须带 `session`（≤128，不含换行），`scope=project` 禁止带 `session`，二者都按闭字段拒绝。`text` ≤4096 且不含 CR，`conditions` ≤16 条适用条件（各 ≤256、不含换行），`sources` ≤32 个 raw 路径。可选宿主元数据：`importance` 为 0..1 的数字；`emotion` 为闭字段对象 `{valence,arousal,dominance}`（各 −1..1）加可选 `label`（1..64、不含换行）；`layer` 取 `judgment`（默认）/`session_summary`/`profile`，其中 `session_summary` 必须 `scope=session`，`profile` 必须 `scope=project`，`episode` 只能由 `memory-promote` 产生。三者进入 `note_hash`，改变即生成新的 superseding 记录，不静默改写。记录内容寻址写入 `state/memory/<workspace>/<id>.json`（记录 v4）：`note_hash`（v5）绑定 workspace/scope/session/kind/text/conditions/sources/source_hashes、`layer` 与可选的 `importance`/`emotion`/`episodic`，`id` 再绑定幂等 `key`，因此租户、可见范围、适用条件和来源版本都属于笔记身份的一部分。同 key 同内容重试在笔记仍为 active 时返回 `replayed`；命中已归档笔记按 `memory_archived_note_refused`（先 `memory-restore`）、命中已替代笔记按 `memory_superseded_note_refused`（对 active 记录重提）拒绝，绝不静默复活不可见笔记。同 key 新内容在同一事务中把旧记录标为 `superseded` 并写 `superseded_by`/`supersedes` 双向链，旧 JSON 保留用于审计；仅当该 key 已有 active 记录时自动 supersede，出现多条 active 记录则拒绝 `memory_key_ambiguous`。不同 key 但内容完全相同拒绝 `memory_duplicate_text`，是否合并由宿主判断——重复与冲突判定都只在同一工作区内进行，两个工作区的相同判断互不影响。来源只登记在 JSON 内（state 条目不能携带目录 sources），撤销或漂移在读取时计算：笔记保留历史，同时显式报告 `valid:false` 与 `invalid_sources`。
- `memory-supersede` 按显式 `id` 替换笔记，继承其 `kind`/`scope`/`layer`、`pinned` 标记与 `importance`/`emotion`/`episodic`/`use_count`（被替代的人工保护和陪伴元数据随替身延续；显式给出 `importance`/`emotion` 可覆盖，旧记录仍保留审计），`key` 省略时沿用旧键；已 superseded 或已 archived 的笔记拒绝，离开归档状态必须先 `memory-restore`。
- `memory-promote`（写，续八十二）：把 `active` 笔记提升为 episode。要求 `importance >= 0.7` 或情感强度 `max(|valence|,|arousal|) >= 0.7`，否则 `memory_promotion_threshold`；通过后在同一事务里 supersede 生成 `layer=episode`/`episodic=true`/`promoted_at=at` 的新记录，继承正文/条件/来源/importance/emotion/use_count 与 pinned，旧记录保留，事件为 `state/events/memory-promote-<old>-<new>.json`。已 episodic 或已替代/归档的笔记拒绝，不调用模型。
- `memory-archive`/`memory-restore` 在 `active` 与 `archived` 之间转移，把笔记移出或移回默认预取范围，`archived_at` 随之写入或清空；重复归档或重复恢复返回 `replayed`，事件路径由 `at` 派生，因此每次状态转移必须提供新的时间戳。所有转移（归档/恢复/pin/supersede）都拒绝早于该笔记 `created_at`/`updated_at` 的 `at`（`memory_time_order_invalid`），`lint` 以 `memory_time_inverted` 报告更早写入的倒序记录。读取时区分两种失效：`invalid_sources` 是来源缺失或已撤销，`drifted_sources` 是来源仍在但字节已变（与记录时的 SHA-256 不同）；`valid` 同时覆盖两者。`inbox` 的 `memory-source-stale` 条目用 `source-revoked-or-drifted` 与 `source-bytes-changed` 两种 reason 分别对应，`lint` 报告 `memory_source_stale` 与 `memory_source_drift`，`stats.memory` 分别计数 `invalid`/`drifted`。没有 `source_hashes` 的旧记录按路径判定，仍然可读。

`memory-list` 需要已登记 `workspace` 与可选 `session`：默认只返回该工作区的 `project` 笔记，显式给出 `session` 时并集该会话的 `session` 笔记；其他工作区的记录既不计数也不可读。返回全部可见笔记、supersede 链、`valid`、`invalid_sources`、`drifted_sources`、`pinned`、`last_used_at`、`importance`、`emotion`、`layer`、`episodic`、`promoted_at`、`use_count` 与 `counts.active/archived/superseded/invalid/drifted`。`memory-read` 按 id 读单条笔记（含 `conditions`、`pinned`、`conflicted` 与来源失效状态），id 不在该工作区可见范围内时统一报 `entry_not_found`，不泄露存在性；避免为读一条判断而列出整个记忆集。`memory-pin` 对 active 笔记设置或清除 `pinned`，已归档/已替代的笔记拒绝：pinned 笔记拒绝 `memory-archive`，对应 A5「保护低频但重要的记忆」，pinned⇒未归档的不变量在两个方向上都成立；相同请求重试返回 `replayed`，事件为 `state/events/memory-pin-<id>-<hash(pinned+at)>.json`。
- `memory-export` 把记忆导出为工作区分层的派生物：`workspaces/projects.json`（全部已登记工作区，按路径稳定排序）与 `workspaces/<workspace>/memory/<id>.md`（仅 `active` 且 `scope=project` 的笔记，frontmatter 含 layer/kind/conditions/sources/importance/emotion/episodic/promoted_at/use_count/valid/invalid_sources/drifted_sources/note_hash，正文即笔记文本）。会话级笔记只计入 `session_notes`，绝不写盘。导出只读权威记录、不写目录、不改变 vault 指纹；重复运行对相同内容零写（`written:0, unchanged:N`），离开 active 集合的笔记会删除对应文件（`removed:N`）。`workspace` 可选：省略时整理全部工作区，给定已登记工作区时只整理该目录，其他工作区的导出保持原样。产物位于 `workspaces/` 派生分层，可整目录删除后重建；`memory-export` 只整理每个工作区的 `memory/` 目录，绝不动同级的 `wiki/`、`claims/`、`manifest.json` 或 `workspaces/index.mbt.md`；外部编辑会在下次导出时被覆盖或清除，绝不反向成为权威，也不与知识页/OKF 导出混用。
`memory-prefetch` 需要已登记 `workspace` 与可选 `session`，可见范围与 `memory-list` 相同；使用与页面检索相同的分词，对 `active`（显式 `archived=true` 时为非 superseded）笔记做 BM25 风格候选排序。种子查询二选一：`query` 由宿主给出，或 `page` 指定一个知识页，用该页 `title` + `body`（截断到 4096 字符）作确定性种子——对应 A5 预取代理「结合当前对话筛选相关内容」，宿主不必从页面里自行提炼关键词。两者同时给出或都缺失都会拒绝；`page` 必须指向已登记知识页。响应以 `query_seed` 标明用了哪一种（`query` 或 `page:<id>`），`limit` 1..50 默认 10，并按约 4096 估算 token 的预算跳过放不下的候选且置 `truncated`。`rank` 默认 `bm25`，保持历史行为；显式 `weighted` 时必须给显式 `now`（严格 ISO-8601 UTC），按 `0.35×相关性 + 0.30×强度 + 0.35×重要性` 重新排序，相关性为 `bm25/(1+bm25)`，强度为 `decay×usage`（半衰期 `30×(1+3×importance+2×intensity)` 天），响应每条候选带 `score_components` 与 `tier`，顶层回显 `rank`/`now`；`now` 在 bm25 模式下禁止。`dedup` 默认 `none`；显式 `similar` 按页面检索同一套规则合并改写变体（分词序列相等且双侧 UTF-8 字节数 ≥64），保留排名靠前的一条并在 `similar_duplicates` 中报告 `{duplicate,keeper}`；相同正文在提交时已被拒绝，因此不提供 `exact`。`kinds` 可按 `preference`/`decision`/`constraint`/`fact`/`goal` 过滤候选，空数组不过滤。返回带 `score`、`conditions`、`valid`、`invalid_sources`、`conflicted` 的笔记，`conflicts` 与 `conflict_counts` 给出检索结果内部同工作区、同可见范围且同条件的冲突分组，以及始终包含的 `overview`（`purpose`、`synthesis`、`synthesis_status`）。`selection:"host_required"` 明确候选筛选与使用方式仍由外部宿主的预取代理决定；核心不调用模型，也不把候选当作已采纳的理解。
- `status`/`stats`/`inbox` 的 `workspace` 与 `session` 均可选：只汇总给定工作区（及会话）可见的记忆；省略 `workspace` 时记忆计数为零、`inbox` 不列记忆条目，避免把多个项目的判断混在一起，也避免默认读取某个工作区。
- `memory-conflicts` 在给定已登记 `workspace` 内列出冲突候选（可选 `session` 同样参与可见性）：同一工作区、同一可见范围（project 或同一 session）内，`kind` 相同、适用条件集合相同（顺序不影响分组）但正文不同的 `active` 笔记归为一组，每组带 `kind`、`conditions` 和逐条 `conflicted:true` 的笔记视图。`superseded`/`archived` 笔记不参与分组，因此替换或归档某一侧会解除冲突；收窄某一侧的适用条件同样解除冲突，因为分组键包含条件。完全相同的正文不算冲突（属于重复，由提交时拒绝）。冲突是待确认的审核债务而非错误：lint 以 warning 报告 `memory_conflict` 并列出相关笔记 id，`status/stats` 的 `memory.conflicted` 计数，两侧记录都保留可读，由宿主通过 `memory-supersede` 或 `memory-archive` 解决。
- `impact-audit` 接收显式 `at`，比较持久化工单冻结的输入与当前 vault，把漂移记录为 `state/impacts/<sha256>.json`。`research` 主题按创建时记录的 `inputs_hash`（purpose、raw、页面、向量的知识指纹，不含 state 记录）比较，因此新登记的材料会产生 `baseline-drift`，而新增工单、建议或再次审计都不会。`overview-suggestion` 按冻结的 `purpose_hash` 与 `page_hashes` 比较，分别产生 `purpose-drift` 与 `page-drift`。`overview-synthesis` 只在没有任何 applied 记录匹配当前 `wiki/overview.md` 时报告 `synthesis-drift`，因此发布更新的综述不会累积记录。记录按 `kind/subject/cause` 内容寻址，一个工单一条；漂移消失时自动置为 `resolved`（`dismissed` 为空），同一漂移重现会重新打开。返回的四个计数语义明确：`opened` 为新建或重新打开的记录数，`updated` 为已有 open 记录因输入再次变化而被刷新的次数（`created_at` 保留，`updated_at` 前进），`resolved` 为漂移消失后自动关闭的次数，`replayed` 为与上次完全相同的次数。`impact-audit` 是只读式的活视图：重复执行不写入、不改变指纹，全部重放时返回 `committed:false`。显式 `key` 只在记录首次创建时生效，用于让宿主控制幂等键。
- `impact-resolve` 记录宿主已处理某条 impact 的决定，写入 `note` 并把 `dismissed` 设为该记录当时的 `current`。此后只有输入再次变化才会重新打开这条 impact——重新提出已被处理的建议必须说明出现了实质变化。相同决定重试返回 `replayed`。`impact-list` 返回全部记录、`subject_present` 与 `counts`；记录参与目录指纹、事务恢复和 pack 往返，open/host-resolved（带 `dismissed`）/auto-resolved 三种状态都完整恢复；`status/stats` 的 `impacts` 报告 `open/resolved/total` 与按 cause 的打开计数。
- `inbox` 是只读汇总入口，把待宿主处理的工作一次列出（可选 `workspace`/`session`：省略 `workspace` 时不汇总任何记忆条目，绝不跨工作区猜测）：打开的 change-impact、`quality-audit` 产生的 pending 审核、`proposed` 研究/目标/综述工单、被来源撤销或互连失效的页面，以及存在但未登记的 raw 文件。`memory-conflicts` 分组出的竞争记忆判断、绑定来源已撤销或漂移的 `memory-source-stale` 记忆笔记也作为待确认项列入，因为它们需要人或宿主确认，而不是静默取舍。每条含 `kind`、`subject`（目录路径）、`reason`、`detail`、`next`（建议操作）和 `created_at`；按 `kind`+`subject`+`reason` 稳定排序，重复调用结果与 vault 指纹都不变。一个 subject 只会被提议一次：若它已有专门条目，漂移原因并入该条目的 `drift` 字段，不再单列 `impact` 条目。已完成、已关闭或已被覆盖的工作不会出现；`items` 为空表示没有值得主动介入的事项。它不调用模型，也不替宿主决定是否执行。
- `purpose-cancel` 与 `overview-cancel` 关闭尚未应用的对应建议工单，写入 `closed_at` 并把状态置为 `cancelled`（`result_hash` 保持为 null）。基线已漂移的建议永远无法应用，取消是把它移出待处理集合的唯一方式；记录与冻结上下文保留用于审计和 pack。相同请求重试返回 `replayed`，已进入终态的建议拒绝。事件分别为 `state/events/purpose-cancel-<id>-<hash(at)>.json` 与 `state/events/overview-cancel-<id>-<hash(at)>.json`。
- `topics` 是只读的主题浏览层，对应 A5 Context 索引中「语义节点按主题组织成可逐层浏览的层次」：只列出 `synthesis` 页（`wiki/overview.md` 与宿主提交的综述页），每条含 `title`、`links`（wikilink 目标）、`sources`、`stale_sources`、`stale`、`sha256` 和 `body_bytes`。entity/concept/source-summary/query 是材料层，不出现在主题列表中。宿主因此可以先浏览主题、再定位材料页、最后回 `raw/` 原文核对，而不必逐页读取。来源被撤销时该来源进入 `stale_sources` 而不是被静默丢弃，同时 `stale` 置真。按页 id 稳定排序，重复调用结果与 vault 指纹都不变。
- `memory-pin` 之外的状态记录都不可被外部直接编辑：任何 op 都以 `@vault.verify` 开头，人工改写 `state/` 记录会以 `content_changed` 拒绝，且 lint 报告 `content_hash_drift`；恢复登记字节后才能继续。`purpose.md` 与知识页的人类编辑则必须显式走 `refresh` 采纳。

- `page-history` 按时间列出某页的完整生命周期：每次 `commit` 记录它发布的页面 SHA-256 与来源，`archive-page`/`restore-page` 记录当时哈希与原因，`forget` 在该页被牵连失效时记录被撤销的来源。对应 A5 Workspace Wiki「页面保留来源引用和版本历史，供用户查阅、核查和修正」。返回 `current`（路径、kind、当前 SHA-256、失效状态、来源）与按 `at` 稳定排序的 `versions`；事件按内容寻址，因此排序键是调用方提供的时间戳。`pages` 字段对本变更前已写入的 `ingest` 事件可缺省，旧事件仍然可读，只是没有逐页历史。

- `execution:"host_required"` 只出现在记录了计划、等待宿主执行的写操作上（`purpose-suggest`、`overview-suggest`、`research-topic`、`review-resolve`、`impact-resolve`）。所有只读操作都不返回该字段——读到它就意味着引擎在等宿主动作，读操作没有这个含义。

- `read-source` 按 id 读取已登记 raw 来源，对应 A5「回原文核对」与 Diff Engine「必要时回查原文」：引擎此前只登记、哈希和引用来源，从不下发字节，宿主只能自行读盘且无法判断读到的是否就是目录登记的那份。返回登记 `format`、`registered_sha256`、`stale`、`verified`（当前 digest 是否仍匹配）、`present` 与 `bytes`；文本来源附 `text`，`binary`/`image` 只报告体积并置 `extraction_required`；`read-source` 本身不触发 OCR，`context` 在 native 宿主配置适配器时可自动抽取，否则交外部调用方。可选 `start`/`end` 取 UTF-8 字节半开区间（与 evidence 锚点同一约定），用于精确核对 `source_start/source_end`；整篇读取按 65536 字节截断并置 `truncated`，显式区间不截断。撤销后的来源保留墓碑条目，读取会报告 `stale:true` 而不是假装字节仍然有效。

- `memory-use` 登记本次前台用到过的记忆笔记（`ids` 1..64、显式 `at`），把 `last_used_at` 写为报告时间。这是 A5 Autodream「长期未用于前台交互的普通记忆应归档」所需要的信号——引擎无法从只读的 prefetch 推断使用情况，因此由宿主显式回报。一次批量报告只写一个事件（`state/events/memory-use-<hash(ids+at)>.json`），整批原子落地；相同请求重试返回 `replayed`。`memory-prefetch` 保持只读，不会自动记录使用。

- `review-resolve` 只记录 `create-page` / `research` / `skip` 决定，后续执行仍交宿主。每条审核记录带 `created_at`、输入快照和质量问题定位；决定带 `at`、`note` 和幂等 `key`，决议事件复制这些关联字段。省略 `key` 时引擎按审核 id、决定、备注和时间确定性生成；相同决定重试只返回 `replayed`，不同决定拒绝。成功决定与 `state/events/review-<id>-<hash(key)>.json` 在同一事务中发布。`backfill` 将显式输入归档成 `raw/queries/<hash>.md` 并进入正常工单；重试不重复。若登记失败，原件保留，下一次 scan 可继续。
- `forget` 的撤销是黏性的：它不删除文件，因此用**完全相同的字节**把文件写回来不会重新登记该来源——那相当于悄悄撤销一个人的撤销决定。重新登记要求内容发生变化（`scan` 才会建新工单）。绑定该来源的记忆笔记在此期间继续报告 `invalid_sources`，直到内容变化后重新登记。

- `stats`、`fingerprints`、`read-log` 提供统计、指纹和事件。`read-log` 可带 `limit`（`0..1000`）读取按稳定事件 id 排序的最后 N 条，省略时返回全部；它不把时间戳当作排序依据。`stats.evidence.coverage` 按页面返回正文 UTF-8 字节并集、有效 claim、万分比覆盖率和重叠区间，并按 raw 来源返回有效 claim/页面覆盖；页面和来源行还给出 `provenance`（`exact`/`legacy`/`mixed`/`legacy_partial`/`invalid`/`none`/`invalidated`），以及来源的 `direct_pages`、`stale_direct_pages`、`support`（`evidenced`/`linked`/`unreferenced`/`invalidated`）和 `basis:"provenance_v1"`，用于区分锚点核验强度与结构性来源覆盖状态。它只衡量已提交区间，不判断语义蕴含。
- WASM 快照会话在同一实例内串行执行异步事务；宿主 `persist` 回调收到版本化快照格式、`base_revision`、新 `revision`、排序文件和 SHA-256，可自行执行 compare-and-swap，并可返回确认的 `revision`；恢复会拒绝 hash 不匹配的快照，旧的无 hash `{revision,files}` 记录可迁移读取。该协议不提供跨实例锁，失败仍必须保留旧快照。

## 其余只读与适配操作

- `read-page` 按 id 读取知识页正文与来源，显式报告 `stale`，并附带该页的 evidence sidecar（逐项 `valid` 与 UTF-8 区间）；页面哈希与目录不一致时拒绝。`list-pages` 返回目录中的知识页条目（id/path/kind/format/sha256/sources/stale）；`read-index` 返回文学化目录源码，`read-purpose` 返回 `purpose.md` 正文，`read-last-valid` 显式读取上次有效目录快照（仍核验所有内容版本，没有静默 fallback）。
- `plan` 列出可继续执行的非终态工单；`cancel` 取消未提交工单；`research-list`/`suggestion-list`/`overview-list` 分别列举研究主题、目标建议和综述建议工单及其状态，供宿主恢复执行。
- `check-index` 实际编译文学化目录并校验引用文件；`recover` 恢复未完成的文件事务并返回是否发生恢复。两者都不改变知识内容。
- `view-init` 创建默认文学化阅读页面（拒绝覆盖），`render-view` 编译声明并输出离线阅读快照；声明细节见 [视觉文档](visual-mbtmd.md)。`import`/`export` 的 OKF/Markdown 互操作规则见 [互操作设计](../specs/engine/interop.md)，容器格式见 [容器文档](pack-format.md)。
- `provider-list` 与 `provider-job-list` 是上面 provider 生命周期的只读列举，字段与对应记录一致。
- `help` 与 `list-tools` 返回同一份工具字典，含每个 op 的字段与 inputSchema。

## MCP

所有操作都同时存在于 CLI 与 MCP：工具名加 `corridor_` 前缀、连字符转下划线，schema 与 CLI 同源。OCR 直接集成不新增 op：nativehost 在既有 `scan`/`refresh` 导入调度与 `context` 兜底上自动抽取；工具字典仍为 139 个，WASM 面不广告 OCR 能力。`scripts/mcp_e2e.py` 对新增操作做真实 JSON-RPC 调用（不只是字典比对），覆盖名称翻译、布尔/数组字段往返、只读操作不返回 `execution`、`memory-prefetch` 的两种种子互斥、`memory-use` 的批量与重放、`page-history`、`purpose-cancel`/`overview-cancel` 的终态与重放、`impact-audit`/`impact-resolve` 的状态机与 dismissed 抑制、`extraction-submit` 的真实入账成功路径（重放与 `extraction_conflict` 也走传输层）、错误信封的 `error_code`。所有 139 个广告工具都有字典/schema 全量比对，其中 134 个还真实走过 `tools/call`（其余 5 个是非 vault 或会话类 op）；探针刻意在 `init` 之前跑——金库未初始化，其余 vault op 必须返回领域 `error_code`，而 `lint`（诊断入口）与 `recover` 必须成功。三个面的 `tools/list` 同源同序（native 字典 schema 与 CLI 逐字节一致，corridor/wasipure 两面的计数与信封行为由各自 e2e 断言）。

启动 `_build/native/debug/build/mcp/mcp.exe`。使用换行 JSON-RPC 2.0 stdio；支持 `initialize`、`notifications/initialized`、`ping`、`tools/list`、`tools/call`。工具前缀 `corridor_`，连字符改为下划线，例如 `corridor_read_page`。`corridor_session_open` 要求 vault，其余工具可在已打开会话中省略 vault；工具列表/schema 与 CLI 来自同一字典。当前支持协议版本 2024-11-05 / 2025-03-26 / 2025-06-18。

三个 MCP 面的传输语义逐面对照：`tools/call` 的 `arguments.receipts` 是 schema 声明的传输字段（编译回执，纯 WASI 面的 `compile_required` 协议依赖它），三个面都接受并剥除——native 面由自身子进程编译，回执不进入引擎；请求行上限逐面不同：native `mcp.exe` 与纯 WASI 面（`wasipure --mcp`）为 2 MiB，超限回复 canonical `parse_error` 信封；corridor wasm 面（`hosts/wasm-host.py --mcp`）经 `input_load` 分段装载达 16 MiB，超限由宿主直写与模块 canonical 形态逐字节一致的 `input_overflow` 信封（含 `data.error_code`/`hint`，无法回显 request_id）。

工具执行失败使用 MCP `isError:true`，结构化结果含 `error_code` 与 `hint`；JSON-RPC 格式或参数错误使用带 `error.data` 的 error 响应。通知不产生响应。`structuredContent` 为 `{result:...}`。进度通知只在调用提供 `_meta.progressToken` 时发送；事件表示同步执行的边界，不承诺运行中取消或后台调度。
