# 实现需求

前置：本轮用户已确认 PROPOSAL 核心方向并要求开始实现。下面把确认过的方向写为可核验需求；不另设重复批准步骤。

1. 当用户初始化并登记资料时，系统应生成真正可经 MoonBit 检查的 index.mbt.md，正文继续作为独立文件存在。声明与内容变化均应触发验证及受影响索引重建。
2. 当 Agent 通过分析、生成、提交工单摄入资料时，系统应校验结构、路径、来源和基线，通过后一致发布；失败不覆盖已有知识；崩溃恢复与重试不重复记账。
3. 当缓存被删除时，系统应能从声明、正文和持久化状态重建，不丢工单/人工决定。当来源撤销时，应排除受影响失效内容，直至重编译。
4. 当用户查询时，系统应支持关键词检索、默认暴力向量检索、图扩展与预算装配；外部 embedding 与搜索实现通过独立抽象接入。不同模型空间与失效向量不得混用。
5. 当 CLI/MCP 调用工具时，系统应从同一字典提供参数说明、结构化结果/错误和可区分进度；未知参数明确拒绝。
6. 当需要呈现页面时，布局/交互应由 views/*.mbt.md 声明，正文经数据绑定引用；目录、搜索、详情和来源跳转应可实际操作，编译失败不破坏知识读取。
7. 产品实现中 MoonBit 有效代码行比例应 >85%；核心不得包含模型/网络调用。测试应覆盖确定性、真实文件损坏、冲突、恢复、来源撤销及有效/无效输入。
8. 容器、OKF 互操作、WASM 与精简 Web 服务按 PROPOSAL 分期交付；不包含桌面应用和专用桌面集成。完成状态逐项记录，不以局部测试替代全范围验收。
